## 0. Design Read

一句话定位：

> 这是**管理员的知识运维台**加**问答侧的证据链**。管理员要在 20–30 个知识库里快速判断「哪份文档没入库、哪块切片切错了、谁能用」；普通用户要在得到答案之后，能一眼看出这句话来自**哪个库、哪份文档、哪一章、第几块**。视觉上继续用现有的 teal + Geist 工作台语言，只在「引用坐标」这一处做记忆点，不做营销页、不做通用 SaaS 卡片墙。

### 0.1 三只旋钮

| 旋钮 | 取值 | 理由 |
| --- | --- | --- |
| `DESIGN_VARIANCE` | 4 | 后台是高频重复操作，布局必须可预测；个性放在「引用坐标」与「入库管道」两个局部 |
| `MOTION_INTENSITY` | 3 | 只有行 hover、抽屉进出、进度推进三种动效；不做滚动揭示、不做呼吸光晕 |
| `VISUAL_DENSITY` | 6 | 列表要能一屏扫完 8–12 行；但行内只放两行文字，不塞 6 个元信息 |

### 0.2 反模板纪律（硬性）

来自 `frontend-design` 的「avoid generic SaaS」与 `design-taste-frontend` 的反默认脸：

- **不新增色板**。全站仍是单一低饱和青主色 + 中性灰；状态色只用已有的 `success / warning / destructive`。禁止紫蓝 AI 渐变、禁止玻璃拟态、禁止彩色光晕。
- **不用卡片网格承载知识库 / 文档 / 专家列表**。这些是运维对象，字段多、要横向比较，一律用**行式列表**（table-like rows）。卡片只出现在「专家选择器」与「专家列表的移动端」，因为那里需要人格化（头像 + 欢迎语）。
- **不用全大写 eyebrow 标签**，不用「词 · 词 · 词」无意义堆叠，不用序号装饰（`01 / 02 / 03`）。
- **不把状态做成纯色块**。状态 = 2px 圆点 + 文字，`Badge variant="outline"`，颜色只做辅助。
- **不做「每个区块都一样圆角加同一种灰影」**。容器用 `rounded-lg` + `border`，只有输入区和抽屉才用阴影。
- **不用插图型空态**。空态 = 一句事实 + 一个下一步按钮。

### 0.3 唯一的记忆点：引用坐标

引用不是「一张漂亮的卡片」，而是一条**可核对的坐标**：

```
K1 · 行政制度 / 员工手册.docx / 第三章 假期管理 › 3.2 年假 / 第 12 块（共 87）
```

- 序号 `K1`、块序号、页码、版本号一律 **Geist Mono + tabular-nums**；
- 文档名与章节路径用正文字体，保持可读；
- 整条坐标默认单行、可换行降级，不用分割线切成三块；
- 点击坐标任意位置都能打开引用详情。

这条坐标在「回答下方」「引用详情抽屉」「管理员切片预览」三处**完全一致**，让用户形成肌肉记忆：看到这个形状，就知道是出处。

## 1. 用户、任务与成功标准

### 1.1 两类角色

| 角色 | 进入方式 | 核心任务 | 使用频率 |
| --- | --- | --- | --- |
| 管理员 `ADMIN` | `/admin/*` | 建库、传文档、盯入库、配专家、发授权 | 低频但重（一次 10–30 分钟） |
| 普通用户 | `/` 问答页 | 选专家提问、核对答案出处 | 高频轻量 |

v1 **没有**团队 / 组织 / 角色授权，只有用户级授权；管理员隐式拥有全部权限。设计上不要出现「部门」「成员组」「角色」这类入口，避免给出不存在的承诺。

### 1.2 核心任务（按优先级）

管理端：

1. 新建知识库 → 上传 `.docx` → 确认切片结果合理 → 授权给用户。
2. 发现某个文档 `FAILED`，看清失败阶段与原因，重试或覆盖上传。
3. 配置专家：写提示词、挂知识库、发授权、发布。
4. 回收权限 / 停用专家时，能预估影响面（谁会用不了）。

用户端：

5. 提问前选中 1–5 个专家（或不选），知道本轮检索范围是什么。
6. 回答里看到 `[K1]`，能在一屏内确认「这段话出自哪份文档的哪一节」。
7. 历史会话回放时，引用仍然可查（哪怕文档已删除）。

### 1.3 成功标准（可验收）

- 管理员从「进入知识库列表」到「文档入库成功可见」≤ 3 次点击 + 1 次拖拽。
- 任一文档失败，**不需要看日志**就能知道卡在 PARSE / CHUNK / EMBED / INDEX 哪一步。
- 用户从回答正文点到「看到原文片段」≤ 2 次点击。
- 引用在文档被删除后仍可展示快照，并明确标注「原文已删除」，不静默消失。
- 全部管理页在 375px 宽度下可完成主流程，无横向滚动。

## 3. 信息架构与路由

### 3.1 路由表

| 路由 | 角色 | 页面 | URL 状态 |
| --- | --- | --- | --- |
| `/admin/knowledge` | ADMIN | 知识库列表 | `?q=&status=&sort=` |
| `/admin/knowledge/[kbId]` | ADMIN | 知识库详情 | `?tab=documents\|grants\|settings`、`?doc=<documentId>` |
| `/admin/experts` | ADMIN | 专家列表 | `?q=&status=` |
| `/admin/experts/new` | ADMIN | 新建专家 | — |
| `/admin/experts/[expertId]` | ADMIN | 编辑专家 | `?tab=profile\|knowledge\|grants` |
| `/` | 登录用户 | 问答页 | 会话侧栏已有 `?session=` 语义，沿用 |

**为什么 tab 与抽屉进 URL**：管理员经常把「某个文档的切片问题」发给同事，或在刷新后回到同一处。`?doc=` 直接打开详情抽屉，`?tab=` 保持分页位置，成本极低但体验差别很大。

### 3.2 导航改造

```ts
// src/app/admin/layout.tsx
const NAV_ITEMS = [
  { href: '/admin/permissions', label: '权限规则', description: '工具基线 / 本人规则', icon: ShieldCheck },
  { href: '/admin/skills',      label: '技能管理', description: '广场 / 安装 / 发布',   icon: Package },
  { href: '/admin/knowledge',   label: '知识库',   description: '文档 / 切片 / 授权',   icon: LibraryBig },
  { href: '/admin/experts',     label: '专家模型', description: '提示词 / 知识库 / 授权', icon: BrainCircuit },
] as const;
```

两点必须同步改：

1. `currentPage(pathname)` 增加两个前缀判断（`/admin/knowledge/xxx` 要归到「知识库」）。匹配顺序按**最长前缀**，避免 `/admin/experts/new` 落到错误标题。
2. 移动端 `<nav className="grid grid-cols-2 ...">` 改为**横向滚动单行**。四个中文标签在 375px 下两列会挤成两行、吃掉 48px 竖向空间；横向滚动只占一行，且手势自然。
3. 单行导航还要补两个细节：激活项进入视口时**自动滚到中间**（否则从侧栏进入「专家模型」时激活项停在屏幕外）；真正被截断的那一侧用 24px `mask-image` 淡出，避免半个 Tab 硬切在屏幕边缘被误读成渲染错误。

```
移动端导航（<lg）

┌──────────────────────────────────────────────┐
│ ⟵ 返回  知识库          ☾   👤              │
├──────────────────────────────────────────────┤
│ [权限规则] [技能管理] [知识库] [专家模型] →  │  ← 横向可滚
└──────────────────────────────────────────────┘
```

## 4. 设计令牌与排版

### 4.1 颜色：零新增色值

**不往 `globals.css` 加任何新颜色变量。** 全部语义映射到现有令牌：

| 语义 | 令牌 | Light 观感 | 用法 |
| --- | --- | --- | --- |
| 页面底 | `--background` | 近白冷灰 | 全局 |
| 容器 | `--card` + `--border/60` | 白 + 极浅边 | 列表容器、抽屉、弹层 |
| 行 hover | `--accent` | 浅青灰 | 列表行、可选行 |
| 选中 | `--primary/10` + `--primary` | 淡青底 + 青字 | 导航、Tab、选中专家 chip |
| 引用标记 | `--primary/10` + `--primary` | 同上 | `K1` 徽标、坐标 hover |
| 成功 | `--success` | 绿 | READY / ACTIVE |
| 进行中 | `--primary` | 青 | PROCESSING 圆点、进度条 |
| 待处理 / 草稿 | `--warning` | 琥珀 | UPLOADED / DRAFT |
| 失败 / 危险 | `--destructive` | 红 | FAILED、删除区 |
| 停用 / 已删除 | `--muted-foreground` | 中灰 | DISABLED / DELETED |

> 为什么要这么克制：现有后台已经有 6 个语义色（primary + skill/tool/thinking/success/warning）。再加一套「知识库紫」「文档蓝」，页面会立刻变成调色盘。**颜色只回答「状态是什么」，不回答「这是哪个模块」。**

### 4.2 字体与数值排版

沿用 `Geist` / `Geist Mono`（`layout.tsx` 已注入 `--font-geist-sans` / `--font-geist-mono`）。

| 用途 | 类 | 说明 |
| --- | --- | --- |
| 页面标题 | `text-xl font-semibold tracking-tight` | 20/28 |
| 区块标题 | `text-sm font-semibold` | 14 |
| 行主标题 | `text-sm font-medium` | 文档名、知识库名、专家名 |
| 正文 | `text-sm leading-relaxed` | 14 |
| 元信息 | `text-xs text-muted-foreground` | 12 |
| 数值 / ID / 版本 / 块序号 | `font-mono text-xs tabular-nums` | **必须 mono**，避免数字跳动 |
| 引用标记 | `font-mono text-[11px] font-medium` | `K1` |
| 提示词正文 | `font-mono text-[13px] leading-6` | 代码式编辑感 |

**数字一律 `tabular-nums`**：文档数、切片数、授权数、块序号在轮询刷新时会变化，等宽数字能防止列表抖动。

### 4.3 间距、圆角、阴影

| 项 | 值 | 用途 |
| --- | --- | --- |
| 间距基数 | 4px | 全站 |
| 页面纵向节奏 | `space-y-6`（区块）/ `space-y-3`（行内） | 与技能页一致 |
| 列表行高 | 56px（单行）/ 64px（双行带描述） | `py-3` + 两行文本 |
| 容器圆角 | `rounded-lg`（10px） | 列表、面板 |
| 控件圆角 | `rounded-md` | 按钮、输入、Tab |
| 抽屉圆角 | 左侧 `rounded-l-xl` | `Sheet` |
| 阴影 | 仅 `shadow-float` 用于 composer；管理页不用阴影 | 管理页靠边框分层 |

### 4.4 状态语义表（全站唯一真相）

| 对象 | 值 | 文案 | 视觉 |
| --- | --- | --- | --- |
| 知识库 | `ACTIVE` | 启用 | success 点 + 文字 |
| | `DISABLED` | 停用 | muted 点 + 文字 |
| | `DELETED` | 已删除 | muted + 删除线（仅在「显示已删除」时出现） |
| 文档 | `UPLOADED` | 待入库 | warning 点 |
| | `PROCESSING` | 入库中 · {阶段} | primary 点 + 轻微脉冲（唯一允许的循环动画） |
| | `READY` | 可检索 | success 点 |
| | `FAILED` | 入库失败 | destructive 点 |
| 版本 | `PENDING` | 排队中 | warning |
| | `PROCESSING` | 处理中 | primary |
| | `READY` | 就绪 | success |
| | `FAILED` | 失败 | destructive |
| 专家 | `DRAFT` | 草稿 | warning 点 |
| | `ACTIVE` | 已发布 | success 点 |
| | `DISABLED` | 已停用 | muted 点 |
| 引用 | 正常 | （无标签） | — |
| | `accessRevoked` | 权限已回收 | warning 条 |
| | `documentDeleted` | 原文已删除 | muted 条 |
| | 无 `citationId` | 详情不可用 | 行不可点，`title` 说明 |

> 状态点**永远不能是唯一信息**，必须带文字。色盲用户与深色模式下都要成立。

## 5. 通用组件规范

### 5.1 `PageHeader`

```
知识库                                    [＋ 新建知识库]
管理 20–30 个知识库，供专家与授权用户检索
```

- 标题 `text-xl font-semibold`；右侧主动作 `Button`（默认尺寸，`h-9`）；
- 副标题可选，`text-sm text-muted-foreground`，一句话说清页面用途；
- 移动端主动作降级为图标按钮，`aria-label` 保留完整文案。

### 5.2 `StatusBadge`

```tsx
<StatusBadge tone="success" label="可检索" />
```

- 结构：`inline-flex items-center gap-1.5 rounded-full border border-border/60 px-2 py-0.5 text-[11px]`；
- 圆点 `h-1.5 w-1.5 rounded-full`，颜色由 `tone` 决定；
- 不使用实心背景色（实心只用于「危险确认」按钮）。

### 5.3 `Toolbar`

- 搜索框：`h-9 w-full max-w-[280px]`，`Search` 图标内嵌左侧，**300ms 防抖**写入 URL；
- 筛选：`Select`（状态），宽度固定 `w-[132px]`；
- 排序：`Select`（最近更新 / 名称 / 文档数）；
- 布局 `flex flex-wrap items-center gap-2`；
- 移动端筛选与排序收进一个「筛选」按钮 + `Sheet`，不横向挤。

### 5.4 行式列表（`DataRow`）

```
┌───────────────────────────────────────────────────────────────────────┐
│ 员工手册.docx            ● 可检索    12/87 块   11-04 14:20      ⋯    │
│ 行政制度 · 1.2 MB · 版本 v3                                           │
└───────────────────────────────────────────────────────────────────────┘
```

规范：

- 整行可点（进入详情），行内操作按钮 `stopPropagation`；
- 行分隔用 `divide-y divide-border/50`，**不给每行加独立边框与圆角**；
- hover 背景 `hover:bg-accent/60`，过渡 `transition-colors duration-150`；
- 键盘：`tabIndex={0}` + `onKeyDown` 处理 Enter/Space，或整行用 `<Link>`（优先 `<Link>`，语义更准）；
- 数值列右对齐（`text-right`），文字列左对齐。

### 5.5 `EmptyState` / `ErrorState`

```
┌─────────────────────────────────────────┐
│  还没有知识库                            │
│  先建一个库，再上传 .docx 文档。          │
│  [新建知识库]                            │
└─────────────────────────────────────────┘
```

- 空态：`rounded-lg border border-dashed border-border px-6 py-12 text-center`；
- 错误态：`border-destructive/30 bg-destructive/5`，`role="alert"`，必须给「重试」按钮；
- 两者都**不使用插画 / emoji**。

### 5.6 危险确认

删除知识库 / 停用专家 / 删除文档，统一用 `AlertDialog`：

- 标题写**对象名**：`删除「行政制度」？`

## 8. 上传与入库：一条可视化的管道

### 8.1 上传对话框（三阶段）

```
① 选择文件                     ② 上传中                    ③ 已提交
┌───────────────────────────┐  ┌───────────────────────┐  ┌──────────────────────┐
│  把 .docx 拖到这里        │  │ 员工手册.docx         │  │ ✓ 已提交入库          │
│  或 [选择文件]            │  │ ▓▓▓▓▓▓▓▓░░░░  72%     │  │ 文档已进入解析队列     │
│                           │  │ 正在上传…             │  │ 可在列表中查看进度     │
│ 仅支持 .docx，≤ 50 MB     │  │                       │  │                      │
│                           │  │                       │  │ [完成] [再传一份]     │
│ 切片策略  (•) 自动  ( ) 目录│  └───────────────────────┘  └──────────────────────┘
│           ( ) 固定          │
│ 自动：有标题结构按章节切，   │
│       否则按固定长度切       │
│              [取消] [上传]  │
└───────────────────────────┘
```

规范：

- `Dialog`，桌面 `max-w-[480px]`；移动端 `inset-x-0 bottom-0 top-auto max-w-none rounded-t-xl`（底部抽屉式），因为手机上「选文件」本身就会拉起系统面板；
- 拖拽区：`rounded-lg border border-dashed`，`dragenter` 时 `border-primary bg-primary/5`；
- **前端预校验**：扩展名必须是 `.docx`（`.doc` / `.pdf` 给出具体提示「请另存为 .docx」/「二期支持 PDF」）、大小 ≤ 50 MB。前端校验只为省一次往返，**后端仍是权威**；
- 上传中显示 `XHR` 真实进度（`fetch` 无上传进度，需要 `XMLHttpRequest` 或 `axios`；v1 用原生 `XMLHttpRequest` 即可，不新增依赖）；
- 上传成功后关闭 Dialog，`toast` + 列表行立即插入一条 `UPLOADED` 记录并开始轮询，不做整页刷新。

### 8.2 入库四段进度（`IngestPipeline`）

后端 `agent_knowledge_ingestion_job` 的 `stage` 是 `PARSE / CHUNK / EMBED / INDEX`，UI 必须原样映射，不要合成一个假百分比：

```
解析文档 ──── 切分章节 ──── 向量化 ──── 写入索引
  ✓            ✓            ● 45%        ○
```

- 四个节点等宽，节点间 1px 连线；已完成 `text-success`，当前 `text-primary` + `animate-pulse`（唯一允许的循环动画），未开始 `text-muted-foreground`；
- 空间不足时（移动端行内）退化为：`● 向量化 · 45%` + 一条 `progress`；
- `aria-live="polite"` 播报阶段切换：`正在向量化，第 39/87 块`（后端若只给总 progress，就播报 `向量化 45%`）。

### 8.3 轮询策略

| 项 | 规则 |
| --- | --- |
| 触发条件 | 列表中存在 `UPLOADED / PROCESSING`，或刚提交上传 |
| 间隔 | 3s（全部就绪后停止） |
| 接口 | `GET /api/admin/knowledge/jobs/{jobId}`（单文档），或列表接口本身返回最新状态时优先用列表 |
| 页面不可见 | `document.visibilityState !== 'visible'` 时暂停，回到可见立即拉一次 |
| 失败退避 | 连续 3 次请求失败 → 间隔降到 10s，并在顶部显示「进度刷新已降级」细条 |
| 结束 | 全部 `READY / FAILED` 后停止轮询，并 `toast` 汇总：`2 份文档入库完成，1 份失败` |

> 20–30 个库、低并发的场景不需要 SSE 推进入库进度。轮询 + 可见性暂停足够，且实现成本低一个数量级。

- 每行：库名 + `文档数 · 切片数` + 状态点；
- 只允许选 `ACTIVE` 库，`DISABLED` 行禁用并标注「已停用」；
- 已选顺序即提示词里出现的顺序（后端 `sort_order`），提供 `上移 / 下移` 两个按钮（不做拖拽，键盘不友好）；
- 允许 0 个（专家仍可用提示词回答），侧栏给警告而不是错误：`未关联知识库：该专家只能凭提示词回答`。

**用户授权**：`UserGrantPicker`：

- 数据源是已存在的 `GET /api/admin/users`（返回全量用户，含 `userId / username / displayName / roles / status`）；
- 前端在 `Command` 内本地过滤（用户名 / 显示名 / 邮箱），**不要求后端加分页**——用户量在内部环境可控；
- 已授权列表显示 `displayName` + `username`（mono）+ 角色徽标；
- 支持批量粘贴 `userId`（换行分隔）一次性添加，这是管理员最常用的姿势；
- 移除授权使用行内 `×`，**不弹确认**（可撤销，且高频）；但移除后侧栏提示「保存后生效」。

### 9.3 发布 / 停用 / 删除

| 操作 | 前置校验 | 确认文案 |
| --- | --- | --- |
| 发布 | 名称非空、提示词非空且 ≤ 6000 | `发布后，14 位已授权用户可以在问答页选择「法务专家」。` |
| 停用 | 无 | `停用后，该专家不再出现在问答页；已授权关系保留，重新发布即可恢复。` |
| 删除 | 无（软删除） | `删除后不可恢复；历史会话中的专家名称快照仍会保留。` |

- 发布/停用后 `toast`，并原地刷新状态徽标，不跳页；
- 若专家处于 `DRAFT` 且未授权任何用户，发布按钮可点，但侧栏给 warning：`还没有被授权用户，发布后暂时无人可见`。

未选择专家时（默认）

┌──────────────────────────────────────────────────────────────┐
│ 输入消息…                                            [发送]   │
├──────────────────────────────────────────────────────────────┤

已选择专家时

├──────────────────────────────────────────────────────────────┤

### 10.3 多选规则

| 规则 | 实现 |
| --- | --- |
| 上限 5 个 | 选满后其余行 `disabled`，面板底部提示 `最多同时选择 5 个专家` |
| 提示词预算（F-10 已定稿） | 后端已改为子 Agent 独立上下文，**不做 12,000 合计上限**，前端不做任何提示词预算拦截；选择面板只展示单专家 `promptChars`，超 6000 由管理端保存时拦截。 |
| 记忆上次选择 | `localStorage['aoteman:experts:' + userId]` 存 `expertId[]`；进入页面时与可用列表求交集，被移除的项**静默丢弃**，只在有变化时 `toast.info('有 1 个专家已不可用，已自动移除')` |
| 只影响下一轮 | 发送时把 `expertIds` 放进 `user.message.payload`；历史消息上方按落盘快照显示当时的专家 chip（只读） |
| 不选专家 | `expertIds: []`，走用户直接授权的知识库；chips 行消失 |

### 10.4 已发送消息上的专家标识

用户消息气泡上方（或气泡内首行）显示当时的专家：

```
┌ 你 ─────────────────────────────────────────────┐
│ 法务专家 · 人事专家                              │  ← 11px 灰字 + 首字头像
│ 年假和竞业限制冲突时怎么处理？                    │
└─────────────────────────────────────────────────┘
```

数据来自 `user.message` 落盘的 `experts` 快照（`ExpertRef[] = { expertId, name, promptHash }`），**不是**实时查专家表——专家改名或删除后，历史消息仍显示当时的名字。旧数据只有 `expertIds` 时显示占位名「专家」，不做实时查询。

### 10.5 错误与降级

| 场景 | 表现 |
| --- | --- |
| 专家已在别处被停用 / 权限被回收（提交后 403） | 消息不写入，`toast.error`：`「法务专家」已停用或无权使用，请重新选择`，自动移除该 chip 并重新打开面板 |
| 专家解析服务不可用（5xx） | `toast.error`：`专家配置暂时不可用，请稍后重试`；**不静默降级为基础问答** |
| `GET /api/experts` 失败 | 选择按钮置灰 + `title="专家列表加载失败"`，旁边一个「重试」文字按钮；问答本身仍可用（不阻塞基础问答） |
| 用户没有任何可用专家 | 隐藏「选择专家」按钮，不显示空面板 |

### 10.6 专家执行状态条（`agent.expert_runs` / `agent.expert_run`）

专家是**并行子 Agent**：主 Agent 要等全部专家结束才开始汇总，这段等待最长 90s。必须有可见进度，否则用户面对的是长时间空白。

后端事件契约（前端只消费，不推断）：

| 事件 | 时机 | 关键字段 |
| --- | --- | --- |
| `agent.expert_runs` | 批次开始 / 结束 | `runId`、`phase=STARTED\|FINISHED`、`mode=PARALLEL`、`parallelism`、`experts[]`（`expertId` / `expertName` / `order` / `status`）、`degraded`、`succeededCount`、`failedCount` |
| `agent.expert_run` | 单专家状态变化 | `runId`、`expertId`、`expertName`、`order`、`status=QUEUED\|RUNNING\|DONE\|FAILED\|CANCELLED\|SKIPPED`、`startedAt`、`finishedAt`、`durationMs`、`errorCode`、`errorMessage`、`truncated` |

渲染位置：**最终回答气泡内部、正文之上**——不放消息列表顶端，也不走全局 toast（离开这一轮就失去上下文）。

```
法务专家 ✓ 8.4s      HR 专家 ✗ 检索超时
```

规范：

- 一行 chips，**严格按 `order` 升序**；不按事件到达顺序（并行完成顺序随机，跳动会让人以为出错）；
- `QUEUED`：灰点 + 名称；`RUNNING`：`animate-pulse` 圆环 + 名称 + `进行中`；
- `DONE`：`✓`（success 语义色）+ 耗时（mono；<60s 显示 `8.4s`，≥60s 显示 `1m30s`）；
- `FAILED`：`✗`（destructive 语义色）+ 单行原因（由 `errorCode` 映射中文，最多一行，`title` 给完整 `errorMessage`）；
- `CANCELLED` / `SKIPPED`：`—` + `已取消` / `已跳过`，中性灰，不用错误色；
- `FINISHED` 且全部 `DONE` 时整行降到 `opacity-60` 但**不删除**——回看历史仍要知道谁参与过；
- 历史回放同样渲染，但**不重播"进行中"动画**，历史状态一律静态；
- 状态条只在选了专家时出现；基础问答不渲染。

降级提示条（`agent.expert_runs(FINISHED).degraded === true`）：

```
⚠ 1 位专家未给出结论：HR 专家（检索超时）。下面的回答只汇总了其余专家。
```

- 位置：状态条下方、回答正文上方；`role="status"`，随流式回答出现一次，不重复播报；
- 部分失败：点名失败专家 + 说明「只汇总其余专家」；
- 全部失败：`本轮专家均未给出结论，以下为基础回答。`——**仍然展示正文**，同时不渲染参考资料区；
- 不把某句话归给某个专家：最终回答是主 Agent 汇总稿，UI 不制造"联合署名"的错觉。

## 11. 用户端 · 引用溯源

### 11.1 数据来源（必须准确）

引用**不额外请求接口**：`agent.citation` 事件随 SSE 推送 / 历史回放一起到达，payload 里已是完整快照：

```json
{ "expertRunId": "xrun_turn_7f3a", "toolCallId": "call_...", "expertId": "exp_legal", "expertName": "法务专家", "citations": [ { "ref": "K1", "citationId": "cit_...", "expertId": "exp_legal", "expertName": "法务专家", "kbName": "...", "documentTitle": "...", "fileName": "...", "headingPath": "...", "pageFrom": 0, "pageTo": 0, "chunkOrdinal": 12, "chunkTotal": 87, "snippet": "...", "vectorScore": 0.83, "rerankScore": 0.91 } ] }
```

只有**打开详情抽屉**时才请求 `GET /api/knowledge/citations/{citationId}`（拿父块、相邻块、原文正文）。

### 11.2 回答正文里的引用标记

`Markdown` 组件增加一个 inline 规则：把 `[K1]`…`[K99]` 渲染为 `CitationRef`。

```
…员工年假需提前三天在系统申请 [K1]，跨年度未休完的部分 [K2]…
                                ↑
                  小号青底等宽徽标，点击打开详情
```

- 样式：`inline-flex items-center rounded bg-primary/10 px-1 py-px font-mono text-[11px] font-medium text-primary align-baseline hover:bg-primary/15`；
- 语义：`<button type="button" aria-label="引用 K1：员工手册.docx 第三章 假期管理">`；
- 只渲染**本轮 citations 里存在的 ref**；模型编造 `[K9]` 时降级为普通文本（不加样式、不可点），避免出现「点开是空的」；
- 同一个 `K1` 在正文出现多次时，全部指向同一 `citationId`。

### 11.3 回答下方「参考资料」

```
参考资料 · 3                                    本轮检索已降级为向量排序 ⓘ
┌──────────────────────────────────────────────────────────────────┐
│ K1  员工手册.docx                                                 │
│     行政制度 · 第三章 假期管理 › 3.2 年假 · 第 12/87 块             │
│     员工年假需提前三天在系统申请，跨年度未休完的部分可顺延至次年…    │
├──────────────────────────────────────────────────────────────────┤
│ K2  报销制度.docx                                                 │
│     财务制度 · 第四章 报销流程 · 第 5/42 块                        │
│     差旅报销需在返回后 15 个工作日内提交…                          │
└──────────────────────────────────────────────────────────────────┘
```

规范：

- 区块标题 `text-xs font-medium text-muted-foreground`，不抢回答正文；
- 每条：`K1` 徽标（mono，固定宽 28px）+ 文档名（medium）+ 坐标行（mono 12px，`·` 分隔）+ snippet（2 行 `line-clamp-2`，点击展开 6 行）；
- **不使用卡片**：用 `divide-y divide-border/50` 的列表，整块无边框无底色，与「过程时间线」的语言一致；
- 页码为空（DOCX 恒为 0）时**整段省略**，不显示「第 0 页」；
- 若 `expertName` 存在，坐标行前置「法务专家 ·」灰字，标明该片段由哪个专家检索到；未选专家时不显示。
- `rerankScore` 为 `null`（降级）时不显示得分；
- 折叠策略：默认展开全部（一轮通常 3–5 条）。超过 5 条时只显示前 5 条 + `展开其余 2 条`。

**模型没有写 `[K*]` 时**：仍然展示该轮 `agent.citation` 的全部条目，但标题改为 `本次检索到的资料 · 3`，并在标题右侧加 `模型未在回答中标注引用` 的灰字说明。不能因为模型偷懒就让用户失去溯源能力。

### 11.4 引用详情抽屉（`CitationSheet`）

右侧 `Sheet`，桌面 `sm:max-w-[480px]`，移动端全宽；标题行 `引用详情` + 关闭。

```
┌ 引用详情 ────────────────────────────────── × ┐
│ K1  员工手册.docx                              │
│ 行政制度 · 版本 v3 · 第 12/87 块               │
│ ─────────────────────────────────────────────  │
│ 章节路径                                        │
│ 第三章 假期管理 › 3.2 年假                      │
│ ─────────────────────────────────────────────  │
│ 快照片段                                        │
│ ┌────────────────────────────────────────────┐ │
│ │ 员工年假需提前三天在系统申请，跨年度未休完  │ │
│ │ 的部分可顺延至次年第一季度…                 │ │
│ └────────────────────────────────────────────┘ │
│ ─────────────────────────────────────────────  │
│ ⓘ 检索得分（管理员可见） 向量 0.83 · 重排 0.91  │
│ ─────────────────────────────────────────────  │
│ [下载原文]              [上一块] [下一块]       │
└────────────────────────────────────────────────┘
```

- 「快照片段」是 `citation.snippet`（当时落库的文本），**不是**实时查库的内容——这是引用可追溯的核心保证；
- 若详情接口返回 `parent`，额外显示「所属章节全文」折叠区（默认收起，`min-h-[120px]`）；
- 「上一块 / 下一块」来自 `chunk.prevChunkId / nextChunkId`，只在该版本内跳转，不切换引用 ref；
- 「下载原文」走 `GET /api/knowledge/citations/{citationId}/document`，用 `<a download>` 触发；`accessRevoked` 或 `documentDeleted` 时按钮不渲染；
- 抽屉打开时 URL 加 `?citation=cit_xxx`（可分享/刷新保持），关闭时移除。

### 11.5 降级与兜底状态

| 状态 | 触发 | 展示 |
| --- | --- | --- |
| 详情不可用 | `citationId == null`（快照落库失败） | 列表行正常展示快照，但**不可点击**，右侧灰字 `详情暂不可用`；不弹任何错误 |
| 权限已回收 | 详情接口 `accessRevoked=true` | 抽屉顶部 warning 条：`你已失去该知识库的访问权限，以下是回答当时的快照`；隐藏「下载原文」与父块全文 |
| 原文已删除 | `documentDeleted=true` | 抽屉顶部中性条：`原文已删除，仅保留当时的快照片段`；隐藏下载与相邻块 |
| 检索降级 | `rerank` 失败 | 参考资料标题右侧 `本轮检索已降级为向量排序` + `Tooltip` 解释「重排服务超时，结果按向量相似度排序」 |
| 专家部分失败 | `agent.expert_runs(FINISHED).degraded=true` 且 `failedCount>0` | 状态条失败项标红 + 回答上方提示条「N 位专家未给出结论」；参考资料区只展示成功专家的引用；最终回答照常展示 |
| 专家全部失败 | `succeededCount=0` | 提示条「本轮专家均未给出结论，以下为基础回答」；**不渲染参考资料区**，正文正常展示，不显示任何专家观点 |
| 无检索结果 | 工具返回空 | 该轮不渲染参考资料区；若回答正文提到资料，属模型问题，不在 UI 处理 |

### 11.6 归组规则

- 一轮（`turnId`）内可能有多次 `knowledge_search`（多步推理），每个 `toolCallId` 对应一个 `agent.citation` 事件；
- 专家模式下 `agent.citation` 按专家分组到达：先按专家 `order` 归组、组内按 `ref` 升序，再整体按全局 `ref` 升序展平；同一 `citationId` 只显示一次（跨专家命中的同一 chunk 已由后端去重归并）；
- 非专家模式即单组，行为与旧逻辑一致；
- 参考资料区挂在该轮**最终回答**下方，而不是每个工具调用后面；
- 历史回放时事件已按 `seq` 排序，渲染逻辑与实时完全一致（同一个组件，不走两条路径）。

### 13.1 底部抽屉的两处实现约束（2026-11-04 校正）

通用 `Dialog` / `Sheet` 本质是「居中弹窗或侧边抽屉」，改造成底部抽屉时踩过两个坑，新增抽屉前先对照：

1. **必须重置位移**：`DialogContent` 自带 `left/top 50%` + `translate(-50%,-50%)`，只覆盖 `inset-x-0 bottom-0` 时全宽抽屉仍会向左上偏移——375px 视口实测 `left: -187.5`，左半屏（标题、拖放区、按钮）被裁掉。底部抽屉要同时写 `translate: 0 0`，并把入场/退场方向由「从左 1/2 处滑入」换成 `slide-in-from-bottom-*`，否则动画仍是斜着飞进来。
2. **绝对定位的关闭按钮会压住右上角内容**：`Dialog`/`Sheet` 的 `X` 固定为 `absolute right-1 top-1 h-11 w-11`。抽屉头部若把计数（如 `2/5`）靠右排，会被完全遮住；头部行需要显式 `pr-14` 让位，而不是靠 `justify-between` 硬挤。

配套细节：底部抽屉统一 `rounded-t-xl` + `pb-[env(safe-area-inset-bottom)]`；上传对话框的 `DialogFooter` 在移动端改成横排，主操作（最后一个按钮）`flex-1` 占满剩余宽度，方便单手拇指触达。

## 15. BFF 与接口映射

### 15.1 代理原则

- 浏览器只访问同源 `/api/**`；**不直连 8081**，不暴露 `X-Internal-Token`；
- 沿用 `src/lib/bff-auth.ts` 的 `bearerHeaders(request)` 透传 JWT；
- 管理端路由在 BFF 层再用 `requireAdmin(request)` 兜底（与 `api/skills` 的 POST 一致），不依赖页面守卫；
- `multipart/form-data` **不要手动设置 `Content-Type`**，让 `fetch` 带 boundary；
- 流式下载用 `res.body` 透传，不整块 `arrayBuffer()`。

### 15.2 环境变量

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:8080` | 已有，数据面（会话 / 技能 / 产物） |
| `CONTROLPLANE_BASE_URL` | `http://localhost:8081` | **新增**，仅服务端使用，不加 `NEXT_PUBLIC_` 前缀 |

> 必须服务端直连 8081：若绕 8080 再转发一次，等于给每个管理请求加一跳，且 agent 的代理层要跟着扩，收益为零。
