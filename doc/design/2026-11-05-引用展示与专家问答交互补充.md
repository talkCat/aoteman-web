# 引用展示与专家问答交互补充

> 适用范围：用户端问答页的「专家多选 + 流式事件 + 引用溯源 + 原文下载」。
> 本文是 `2026-11-04-知识库与专家模块-前端接口清单.md` 的**会话事件协议补充**，
> 与 `2026-11-04-知识库与专家模型前端设计.md` §10 / §11 配套阅读。
> 后端实现基线：Task 10 / 11A / 11B / 12（2026-11-05 完成）。

## 0. 一句话结论

问答页只需要对接两条链路：

1. **HTTP**：`GET /api/experts`（专家列表）、`GET /api/knowledge/citations/**`（详情 / 邻块 / 下载）；
2. **SSE**：`GET /api/sessions/{sessionId}/events/stream`，消费
   `agent.expert_runs`、`agent.expert_run`、`agent.citation`、`agent.message` 四类事件。

专家选择只影响**这一轮**的检索与子 Agent 编排；引用只在**这一轮**内编号（`K1…Kn`），
不要跨轮复用。

---

## 1. 交互时序

```text
用户勾选专家（≤5）
  └─ POST /api/sessions/{sessionId}/events
       events: [{ type: "user.message",
                  payload: { text, deepThinking, expertIds: ["exp_a","exp_b"] } }]

SSE：
  agent.expert_runs (STARTED)      → 状态条：全部专家 QUEUED，按 order 排序
  agent.expert_run  (RUNNING/DONE/FAILED/CANCELLED/SKIPPED) → 更新单个专家
  agent.expert_runs (FINISHED)     → 状态条收口；degraded=true 时插入降级提示条
  agent.citation    (每位专家一条) → 参考资料卡片追加
  agent.message                    → 最终回答；正文 [K*] 变为可点击标记
```

要点：

- **先 FINISHED 再 citation**：后端保证顺序，前端不需要自己等待；
- 事件可能因断线重连被回放，**所有处理必须幂等**（按 `runId + expertRunId` / `ref` 去重）；
- 历史回放与实时推送使用同一套渲染逻辑，不要写两条路径。

## 2. 专家多选

### 2.1 数据源

```http
GET /api/experts
```

```json
[{
  "expertId": "exp_a",
  "name": "制度专家",
  "description": "解读行政与人事制度",
  "avatarUrl": null,
  "welcomeMessage": null,
  "kbIds": ["kb_1"]
}]
```

- 只返回当前用户被授权且状态为 `ACTIVE` 的专家；
- **不下发 `systemPrompt`**，前端也不允许展示或缓存提示词；
- 列表为空表示「暂无可选专家」，仍允许普通问答。

### 2.2 选择规则

| 规则 | 说明 |
| --- | --- |
| 上限 | 最多 **5** 个；后端 `ExpertSelectionPayload.MAX_EXPERTS=5` 同样校验，超限 400 |
| 去重 | 按选择顺序保序去重，后端会再 trim / 去空 |
| 可取消 | 再次点击取消选择；输入框上方徽标显示 `专家 · N` |
| 记忆范围 | **仅当前会话的下一轮**；发送后是否保留由产品决定，默认保留到用户手动清空 |
| 服务不可用 | 列表请求失败时展示「专家服务暂不可用，本次将按普通问答发送」，**绝不阻塞发送** |

### 2.3 发送载荷

```json
{
  "userId": "user_xxx",
  "events": [{
    "type": "user.message",
    "payload": {
      "text": "年假怎么申请？",
      "deepThinking": false,
      "expertIds": ["exp_a", "exp_b"],
      "turnId": "turn_01JABCDEF..."
    }
  }]
}
```

- `expertIds` 缺省或空数组 = 普通问答；
- `turnId` 可选。缺省由后端生成 `turn_<ULID>`；显式传入必须匹配 `[A-Za-z0-9_-]{8,64}`；
- 同一 `turnId` 重试是幂等的，可用于断线重发。

## 3. SSE 事件协议

### 3.0 通用帧

事件名 = `event:` 字段，`data:` 是 `ConversationEventDto`：

```json
{
  "id": "ev_123",
  "sessionId": "sess_xxx",
  "seq": 42,
  "type": "agent.citation",
  "payload": { },
  "processedAt": null,
  "createdAt": 1762345678901
}
```

- `seq` 单调递增；预览帧（`event_delta` 等）固定 `-1`，不写历史；
- 前端按 `seq` 去重即可安全处理重连回放；
- `payload` 内不允许出现 `systemPrompt`、专家内部思考或内部工具入参。

### 3.1 `agent.expert_runs` — STARTED

```json
{
  "runId": "run_xxx",
  "phase": "STARTED",
  "mode": "PARALLEL",
  "parallelism": 3,
  "experts": [
    { "expertRunId": "run_xxx:exp_a", "expertId": "exp_a", "expertName": "制度专家",
      "order": 1, "status": "QUEUED" }
  ]
}
```

### 3.2 `agent.expert_runs` — FINISHED

```json
{
  "runId": "run_xxx",
  "phase": "FINISHED",
  "mode": "PARALLEL",
  "degraded": true,
  "succeededCount": 1,
  "failedCount": 1,
  "cancelledCount": 0,
  "totalDurationMs": 1200,
  "dedupedCount": 0,
  "digestTruncated": false,
  "digestChars": 120,
  "digestHash": "…",
  "digest": "内部摘要（不得展示）",
  "experts": [
    { "expertRunId": "run_xxx:exp_a", "expertId": "exp_a", "expertName": "制度专家",
      "order": 1, "status": "DONE", "startedAt": 1, "finishedAt": 900,
      "durationMs": 899, "errorCode": null, "errorMessage": null,
      "truncated": false, "droppedByBudget": false }
  ]
}
```

> ⚠️ `digest` / `digestHash` / `digestChars` 是**主 Agent 的内部输入**，只用于排障统计；
> 前端**禁止渲染 digest 原文**。界面上只允许出现「成功 N · 失败 M」与错误码/错误信息。

### 3.3 `agent.expert_run`

```json
{
  "runId": "run_xxx",
  "expertRunId": "run_xxx:exp_b",
  "expertId": "exp_b",
  "expertName": "流程专家",
  "order": 2,
  "status": "FAILED",
  "startedAt": 1,
  "finishedAt": 800,
  "durationMs": 799,
  "errorCode": "EXPERT_TIMEOUT",
  "errorMessage": "专家执行超时",
  "truncated": false
}
```

状态机：

```text
QUEUED → RUNNING → DONE
                 ├→ FAILED
                 └→ CANCELLED
QUEUED ──────────→ SKIPPED
```

### 3.4 `agent.citation`

每位专家**只发一条**聚合事件；顶层不带 `toolCallId`，卡片内部保留：

```json
{
  "runId": "run_xxx",
  "expertRunId": "run_xxx:exp_a",
  "expertId": "exp_a",
  "expertName": "制度专家",
  "order": 1,
  "citations": [{
    "ref": "K1",
    "finalRank": 1,
    "citationId": "cit_xxx",
    "toolCallId": "call_xxx",
    "expertId": "exp_a",
    "expertName": "制度专家",
    "kbId": "kb_1",
    "kbName": "行政制度",
    "documentId": "doc_xxx",
    "documentTitle": "员工手册",
    "fileName": "员工手册.docx",
    "versionId": "ver_xxx",
    "chunkId": "ck_xxx",
    "parentChunkId": "ck_pxxx",
    "headingPath": "第三章 > 3.2 年假",
    "pageFrom": 0,
    "pageTo": 0,
    "chunkOrdinal": 12,
    "chunkTotal": 87,
    "snippet": "员工累计工作满一年……",
    "vectorScore": 0.83,
    "rerankScore": 0.91
  }]
}
```

- `ref` 是**本轮全局编号**（跨专家连续），用于正文 `[K*]` 与卡片互指；
- `citationId` 可能为 `null`：表示引用尚未落库，卡片只读、不可打开详情；
- `finalRank` 为 `null`：尚未最终排序，文案从「排序 #N」降级为「参考 N」；
- 同一 `ref` / `citationId` 重复到达时只保留第一条。

## 4. 渲染规则

### 4.1 专家状态条

- 聚合键：`runId`；同一轮只渲染一条状态条；
- **按 `order` 升序排列，禁止按事件到达顺序**（并行执行时 `RUNNING` 到达顺序是乱的）；
- 每个专家显示：名称 + 状态文案 + 耗时（`durationMs`，有值才显示）+ 失败原因（`errorMessage`）；
- 状态文案：`QUEUED=排队`、`RUNNING=执行中`、`DONE=完成`、`FAILED=失败`、
  `CANCELLED=已取消`、`SKIPPED=已跳过`；
- 失败项标红，但仍保留在列表中，不隐藏。

### 4.2 降级提示条

`FINISHED.degraded === true` 时，在最终回答**上方**插入提示条：

```text
部分专家未能完成，本次回答已降级（流程专家：专家执行超时）。
```

- 全部失败（`succeededCount === 0`）时文案改为「本轮专家均未给出结论，以下为基础回答」；
- 降级提示**不影响**最终回答与基础引用展示；
- 提示条不包含 digest、不包含内部错误堆栈。

### 4.3 最终回答

- `agent.message` 是该轮唯一权威回答；
- 正文 `[K1]`…`[K99]` 只对本轮已到达的 `citations[].ref` 生效；
- 模型编造的 `[K9]`（本轮无此 ref）按普通文本渲染，不可点击。

## 5. 参考资料卡片

- 分组标题固定为「本次检索到的资料」，右侧显示条数；
- **模型没写 `[K*]` 也要展示全部引用**（溯源能力不能依赖模型自觉）；
- 卡片排序：`finalRank` 升序；`finalRank` 为空时按 `ref` 数字升序排在后面；
- 每张卡片显示：`ref` 徽标、文档标题、专家名、知识库名、`headingPath`、
  `切片 ordinal/total`、排序位次、相关度（`rerankScore`，为空则用 `vectorScore`，都为空不显示）；
- `citationId` 为空：卡片加「草稿」态，不可点击；
- 同一 `citationId` 跨专家只展示一次（后端已按 chunk 去重，前端再做一次兜底）。

## 6. `[K*]` 与卡片双向定位

| 操作 | 行为 |
| --- | --- |
| 点击正文 `[K1]` | 滚动到对应卡片并高亮 1.4s；找不到给 toast 提示 |
| 点击卡片标题/徽标 | 滚动回正文第一个 `[K1]` 并高亮 |
| 点击卡片其他区域 | 打开引用详情抽屉 |
| 卡片在视口外 | 使用 `scrollIntoView({ block: "center", behavior: "smooth" })` |

无障碍要求：正文标记必须是 `<button type="button">`，`aria-label` 带文档名与章节，
键盘 `Enter` / `Space` 可触发。

## 7. 引用详情抽屉

### 7.1 详情接口

```http
GET /api/knowledge/citations/{citationId}
```

```json
{
  "citation": { "…": "CitationView，同 agent.citation 卡片" },
  "chunk": { "chunkId": "ck_x", "content": "…", "prevChunkId": "ck_0", "nextChunkId": "ck_2" },
  "parent": { "chunkId": "ck_p", "content": "…", "headingPath": "第三章 > 3.2 年假" },
  "document": { "documentId": "doc_x", "title": "员工手册", "fileName": "员工手册.docx", "fileExt": "docx" },
  "accessRevoked": false,
  "documentDeleted": false
}
```

- `chunk` 是命中的 **CHILD** 块；`parent` 只在对目录切分（父子块）时存在，固定切片策略下为 `null`；
- `prevChunkId` / `nextChunkId` 为空串表示没有相邻块；
- 非本人且非管理员 → **404 `CITATION_NOT_FOUND`**（不泄露存在性）。

### 7.2 邻块接口（新增）

```http
GET /api/knowledge/citations/{citationId}/chunks/{chunkId}
```

```json
{
  "chunkId": "ck_2",
  "content": "……",
  "prevChunkId": "ck_1",
  "nextChunkId": "ck_3"
}
```

- 仅允许读取**同一引用、同一文档版本内**的 `CHILD` 块；越界 / 跨版本 / 非 CHILD 一律 404；
- `410 DOCUMENT_UNAVAILABLE`：授权回收或文档删除；
- `404 CITATION_NOT_FOUND`：引用不可见；
- `404 CHUNK_NOT_FOUND`：切片不存在或不属于该引用。

> 前端「上一块 / 下一块」只调用这个接口，不要拼接文档切片列表接口
> （`/api/admin/**` 需要管理员权限，普通用户不可用）。

### 7.3 抽屉展示

```text
标题：文档标题            [K1] · 知识库：行政制度 · 专家：制度专家 · 第三章 > 3.2 年假 · 切片 12/87
─────────────────────────────────────────────
命中切片（子块）
  正文……

父块 · 第三章 > 3.2 年假          （仅父子块策略）
  父块正文……

来源文档
  员工手册.docx · docx
─────────────────────────────────────────────
[上一块] [下一块]                    [下载原文]
```

- 打开时先渲染卡片快照（标题/路径/片段），详情请求返回后再补正文，避免白屏；
- 快速切换引用时用 `token` 丢弃过期响应；
- 抽屉关闭或切换引用时重置上一块/下一块与下载按钮状态。

## 8. 原文下载

```http
GET /api/knowledge/citations/{citationId}/document
```

- 成功：`200` + DOCX MIME + `Content-Disposition: attachment; filename*=UTF-8''...`；
- 失败：`410 DOCUMENT_UNAVAILABLE`（授权回收 / 文档删除）、
  `404 DOCUMENT_NOT_FOUND`（版本或物理文件缺失）、`404 CITATION_NOT_FOUND`；
- **固定下载引用行里的 `versionId`**，不跟随文档最新版本（审计语义）；
- BFF 必须流式透传 `res.body`，不要 `arrayBuffer()` 全量缓冲；
- 文件名优先用 `citation.fileName`，缺失时用 `documentTitle + ".docx"`。

权限矩阵：

| 场景 | 详情接口 | 邻块接口 | 下载接口 | UI |
| --- | --- | --- | --- | --- |
| 正常 | 200 | 200 | 200 | 全部可用 |
| 授权被回收 | 200 + `accessRevoked=true` + `chunk/parent=null` | 410 | 410 | 快照 + 提示条；下载禁用 |
| 文档已删除 | 200 + `documentDeleted=true` + `chunk/parent=null` | 410 | 410 | 快照 + 提示条；下载禁用 |
| 非本人 / 非管理员 | 404 | 404 | 404 | 提示「引用不存在或无权查看」 |

> 抽屉在 `accessRevoked` / `documentDeleted` 时**保留**来源文档与引用元数据（快照），
> 只移除正文与下载能力。不要整块清空抽屉。

## 9. 同源 BFF 约定（红线）

- 前端默认**同源**访问：`/api/**` 由 BFF 反代到控制面（8080）与数据面（8081）；
- 禁止在页面里硬编码内网地址（如 `http://10.26.0.2:8082`）或嵌入 JWT；
- 若需要跨域调试，只能通过 `window.AOTEMAN_API_BASE` 注入，且该值由部署层提供，
  不得提交到仓库；
- SSE 连接同样走 `API_BASE`，并携带登录态（Cookie 或 BFF 注入的 Header）；
- 401 统一跳登录；403 按「无权限」提示；404 按「不存在或无权查看」提示（不区分）。

## 10. TypeScript 类型

```ts
export type ExpertRunStatus = "QUEUED" | "RUNNING" | "DONE" | "FAILED" | "CANCELLED" | "SKIPPED";

export interface ExpertRunSnapshot {
  expertRunId: string;
  expertId: string;
  expertName: string;
  order: number;
  status: ExpertRunStatus;
  startedAt: number | null;
  finishedAt: number | null;
  durationMs: number | null;
  errorCode: string | null;
  errorMessage: string | null;
  truncated: boolean;
  droppedByBudget?: boolean;
}

export interface ExpertRunsStartedPayload {
  runId: string;
  phase: "STARTED";
  mode: "PARALLEL";
  parallelism: number;
  experts: ExpertRunSnapshot[];
}

export interface ExpertRunsFinishedPayload {
  runId: string;
  phase: "FINISHED";
  mode: string;
  degraded: boolean;
  succeededCount: number;
  failedCount: number;
  cancelledCount: number;
  totalDurationMs: number;
  dedupedCount: number;
  digestTruncated: boolean;
  digestChars: number;
  digestHash: string;
  /** 内部摘要，禁止渲染 */
  digest: string;
  experts: ExpertRunSnapshot[];
}

export interface ExpertCitationPayload {
  runId: string;
  expertRunId: string;
  expertId: string;
  expertName: string;
  order: number;
  citations: CitationView[];
}

export interface ChunkView {
  chunkId: string;
  content: string;
  prevChunkId: string;
  nextChunkId: string;
}
```
