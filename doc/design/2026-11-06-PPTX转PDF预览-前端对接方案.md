## 2. 交互设计

### 2.1 画布布局

```text
┌──────────────────────────────────────────────────────────┐
│ 画布头部：文件名 · PPTX · 大小 · [下载 PPTX] [在新标签打开] │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                    预览区（flex-1）                       │
│   ready      → <iframe> PDF，白底页面浮在深色轨道上        │
│   converting → 骨架 + 「正在生成预览…」+ 进度呼吸光         │
│   failed     → 失败说明 + [重试] + [下载 PPTX]            │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ 底部信息条（可折叠）：类型 · 修改时间 · 工作区路径 [复制]   │
└──────────────────────────────────────────────────────────┘
```

设计要点：

1. **预览区占满剩余高度**，不再像现在这样「一张居中的信息卡」；文件信息下移成辅助信息条，避免主次颠倒。
2. PDF 页面本身是白底，**外层轨道**用主题色（深色模式用 `bg-surface-1`，浅色用 `bg-surface-2`），加 `px-4 py-4`，让 PDF 像一张「纸」浮在上面 —— 这是本次立体感的关键。
3. 不做缩放工具条：浏览器 PDF 查看器自带；重复造会与原生交互打架。
4. iframe 必须有 `title`（无障碍）与固定 `key`（避免重渲染导致 PDF 重新加载、跳回第 1 页）。

### 2.2 视觉规范（贴合灵犀现有体系）

| 元素 | 样式 |
| --- | --- |
| 预览轨道 | `rounded-xl border border-line-1 bg-surface-1 p-3 shadow-[inset_0_1px_0_rgba(255,255,255,0.04)]` |
| iframe 容器 | `rounded-lg overflow-hidden bg-white ring-1 ring-black/10` |
| 头部操作按钮 | 复用 `btn-raised` / `ui-pressable` / `ui-focus-ring`（与现有画布一致） |
| 加载骨架 | 三张「页面」占位，`animate-pulse` + 主题色顶部微光条，**不要**用转圈 spinner 当主视觉 |
| 失败态 | 与 `MarkdownArtifactView` 的错误态同款图标 + 文案层级 |
| 深/浅色 | 只换轨道与文字色，**禁止**对 PDF 做 `filter: invert()` |

> 现状问题：`PptxArtifactView` 的脚注文案是「本期不提供页面级预览」，实现后必须删掉，不能留旧话术。

### 2.3 状态与文案

| `previewStatus` | 预览区 | 主文案 | 次文案 | 主操作 |
| --- | --- | --- | --- | --- |
| `pending` | 骨架 | 正在准备预览… | 首次生成约 5–15 秒 | 下载 PPTX |
| `converting` | 骨架 + 呼吸光 | 正在生成预览… | 可先下载，稍后再看 | 下载 PPTX |
| `ready` | iframe | — | — | 下载 / 新标签打开 |
| `failed` | 失败卡 | 没能生成预览 | 按错误码给一句话（见 §3.4） | 重试 / 下载 PPTX |
| `none`（老服务端无字段） | 信息卡 | — | 保持当前「文件信息 + 下载」行为 | 下载 PPTX |

**文案红线**：不写「加载失败，请刷新页面」这类甩锅文案；必须告诉用户「还能下载」。

### 2.4 交互细节

| 交互 | 行为 |
| --- | --- |
| 打开画布 | 若 `previewStatus !== 'ready'` → 立即 `POST`-less 触发一次 `GET /preview`（服务端入队并返回 202），随后开始轮询 |
| 切到别的产物 | `AbortController.abort()` + 递增 `generation`，旧响应一律丢弃 |
| 画布关闭 | 停止轮询；**不取消**服务端转换（转换本身有价值，下次打开即命中） |
| 页面切到后台 | `document.visibilityState === 'hidden'` 暂停轮询，回到前台立即补一次 |
| 下载 | 始终指向 `artifactContentUrl(..., download=true)`，不受预览状态影响 |
| 重试 | `GET /preview/status?…&retry=true` 后再 `GET /preview`，重置轮询计数（每次打开最多 3 次） |
| 演示产物 | `isDemoArtifact()` 为真时**不发任何请求**，保持当前禁用的下载按钮与说明 |
| 90s 仍未就绪 | 停止轮询，显示「仍在生成」+ 「重新检查」按钮（手动触发一次 status） |

## 3. 数据与接口层

### 3.1 类型扩展（`src/lib/artifacts.ts`）

```ts
export type PreviewKind = 'none' | 'pdf';
export type PreviewStatus = 'none' | 'pending' | 'converting' | 'ready' | 'failed';

export interface ArtifactItem {
  // …现有字段保持不变…
  previewKind?: PreviewKind;      // 服务端未升级时缺省
  previewStatus?: PreviewStatus;
  previewErrorCode?: string | null;
  previewUpdatedAt?: number;
}

export interface ArtifactPreviewStatus {
  workspacePath: string;
  previewKind: PreviewKind;
  previewStatus: PreviewStatus;
  previewErrorCode: string | null;
  retryAfterMs: number;
  updatedAt: number;
  size: number;
  modifiedAt: number;
}
```

> 全部新增字段用**可选**，保证前端可以先合入、服务端后上线（老服务端返回 undefined 时走 `none` 分支）。

### 3.2 客户端函数

```ts
/** 预览状态查询（不触发转换）。 */
export async function fetchArtifactPreviewStatus(
  userId: string,
  sessionId: string | undefined,
  workspacePath: string,
  options?: { retry?: boolean; signal?: AbortSignal }
): Promise<ArtifactPreviewStatus>;

/** 触发 / 获取预览：首次会入队并返回 202。 */
export async function requestArtifactPreview(
  userId: string,
  sessionId: string | undefined,
  workspacePath: string,
  options?: { warmup?: boolean; signal?: AbortSignal }
): Promise<{ status: number; previewStatus?: PreviewStatus; retryAfterMs?: number }>;

/** iframe 用地址（同源 BFF，可带版本号防缓存）。 */
export function artifactPreviewUrl(
  userId: string,
  sessionId: string | undefined,
  workspacePath: string,
  version?: number      // 建议传 modifiedAt，源文件变了 URL 也变
): string;
```

`version` 作用：源文件被重新生成时 `modifiedAt` 变化，iframe `src` 变化 → 浏览器重新拉取，避免显示旧 PDF。

### 3.3 新增 BFF 路由

#### `src/app/api/artifacts/preview/status/route.ts`

```ts
export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

export async function GET(request: NextRequest) {
  // 透传 workspacePath / userId / sessionId / tenantId / retry
  // 用 bearerHeaders(request) 带上鉴权
  // 后端非 2xx 时，把 { error, code } 原样回给浏览器（前端按 code 分支）
}
```

#### `src/app/api/artifacts/preview/route.ts`

关键点（比现状 `content/route.ts` 多三件事）：

```ts
export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

async function proxy(request: NextRequest, method: 'GET' | 'HEAD') {
  const headers = bearerHeaders(request);
  const range = request.headers.get('range');
  if (range) headers.Range = range;              // ① 透传 Range

  const res = await fetch(target, { method, cache: 'no-store', headers });

  const out = new Headers({ 'cache-control': 'no-store' });
  ['content-type', 'content-disposition', 'content-length',
   'content-range', 'accept-ranges', 'etag'].forEach(k => {   // ② 透传 206 相关头
    const v = res.headers.get(k);
    if (v) out.set(k, v);
  });

  if (method === 'HEAD') return new NextResponse(null, { status: res.status, headers: out });
  return new NextResponse(res.body, { status: res.status, headers: out });  // ③ 流式转发，不再 arrayBuffer
}
```

**为什么必须做 ①②③**：Chromium 内嵌 PDF 查看器会发 `Range` 请求，BFF 若用 `arrayBuffer()` 且丢掉 `206/Content-Range`，浏览器会认为响应不完整，表现为**白屏或无法翻页**。这是本方案最容易踩的坑。

`202` 的 body 是 JSON，也需要原样转发，前端据此拿到 `retryAfterMs`（读不到就用默认 1500ms）。

### 3.4 错误码 → 文案映射

| `code` | 文案 | 附加操作 |
| --- | --- | --- |
| `PREVIEW_NOT_READY` | 预览还在生成中 | 继续轮询 |
| `SOURCE_NOT_FOUND` | 文件已不存在，可能被清理了 | 关闭画布 |
| `UNSUPPORTED_FORMAT` | 该格式暂不支持预览 | 下载 |
| `PREVIEW_DISABLED` | 服务端未开启预览 | 下载 |
| `CONVERTER_UNAVAILABLE` | 预览服务暂不可用（请联系管理员） | 下载 |
| `CONVERT_TIMEOUT` | 生成超时，文件可能过于复杂 | 重试 / 下载 |
| `CONVERT_FAILED` | 无法生成预览，文件可能已损坏 | 重试 / 下载 |
| `SOURCE_TOO_LARGE` | 文件过大，暂不支持在线预览 | 下载 |
| `QUEUE_FULL` | 正在排队，请稍候 | 5s 后自动重试 |

## 4. 组件与状态设计

### 4.1 `useArtifactPreview`（新增 `src/hooks/useArtifactPreview.ts`）

```ts
export interface PreviewState {
  status: PreviewStatus;
  errorCode: string | null;
  version: number;          // 用 modifiedAt 当版本
  timedOut: boolean;        // 90s 上限
  retry: () => void;
}

export function useArtifactPreview(args: {
  userId: string;
  sessionId?: string;
  artifact: ArtifactItem;
  enabled: boolean;         // 画布是否可见
}): PreviewState;
```

内部行为：

| 点 | 做法 |
| --- | --- |
| 初始状态 | 取 `artifact.previewStatus ?? 'none'`，**不额外请求** |
| 触发 | `enabled && status !== 'ready' && status !== 'none'` 时调一次 `requestArtifactPreview` |
| 轮询 | `setTimeout` 递归（不用 `setInterval`，避免请求重叠）；间隔取 `retryAfterMs`（钳在 1000–3000ms） |
| 退避 | 连续 20 次未完成 → 间隔 ×1.5（上限 5s） |
| 停止 | `ready` / `failed` / `none` / 90s / 组件卸载 / `AbortController` 触发 |
| 可见性 | `visibilitychange` 暂停 / 恢复 |
| 竞态 | 以 `workspacePath` 为 key 的 `generationRef`，响应回来先比对，不一致直接丢 |
| 错误 | 网络错误不直接把状态改成 `failed`，而是累计 3 次后才展示「连接失败」，避免抖动 |

### 4.2 `PptxArtifactView` 结构

```tsx
export function PptxArtifactView({ artifact, userId, sessionId }) {
  const demo = isDemoArtifact(artifact.workspacePath);
  const preview = useArtifactPreview({ userId, sessionId, artifact, enabled: !demo });

  return (
    <div className="flex h-full min-h-0 flex-col">
      <PptxPreviewPane preview={preview} artifact={artifact} userId={userId} sessionId={sessionId} />
      <PptxMetaBar artifact={artifact} userId={userId} sessionId={sessionId} demo={demo} />
    </div>
  );
}
```

- `PptxPreviewPane`：`ready` 渲染 iframe；`pending/converting` 渲染 `PptxPreviewSkeleton`；`failed` 渲染 `PptxPreviewError`；`none` 渲染现有信息卡（老服务端 / demo）。
- `PptxMetaBar`：一行紧凑信息（大小 · 修改时间 · 路径 · 复制）+ 右侧「下载 PPTX / 在新标签打开」。

**iframe 写法**

```tsx
<iframe
  key={`${artifact.workspacePath}:${preview.version}`}
  src={artifactPreviewUrl(userId, sessionId, artifact.workspacePath, preview.version)}
  title={`${artifactFileName(artifact.workspacePath)} 预览`}
  className="h-full w-full rounded-lg bg-white"
/>
```

- 不设 `sandbox`（同源 PDF 查看器需要正常运行）；
- 不设 `loading="lazy"`（画布内本来就要立即显示）；
- 高度：容器 `h-full min-h-[420px]`，移动端 `min-h-[60vh]`。

### 4.3 演示模式（`?preview=1`）

`isDemoArtifact()` 为真时：

- 不调 `requestArtifactPreview` / `fetchArtifactPreviewStatus`；
- `PptxPreviewPane` 直接渲染静态说明卡（与当前实现一致），**不伪造 PDF**；
- 下载按钮保持禁用并保留 title 说明。

## 5. 降级与边界

| 场景 | 前端行为 |
| --- | --- |
| 服务端未升级（无 `previewKind`） | 走 `none` 分支，与今天完全一致 |
| BFF 502/504 | 3 次内重试，仍失败 → 失败态 + 下载 |
| iframe 迟迟不触发 load（> 20s） | 显示「用新标签打开」提示，不替换为错误页 |
| 浏览器不支持内嵌 PDF（部分 Firefox） | `onLoad` 不触发时给「在新标签打开」链接；这是浏览器策略，不是缺陷 |
| PDF 体积大（> 20 MB） | 依赖浏览器按需 Range 加载，前端不做预下载 |
| 用户快速连点「重试」 | 按钮 500ms 内禁用，避免打爆转换队列 |
| 画布宽度 < 720px | 隐藏信息条右侧次要信息，保留下载与预览 |
