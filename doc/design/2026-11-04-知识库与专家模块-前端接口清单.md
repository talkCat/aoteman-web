## 0. 通用约定

### 0.1 基地址与代理

| 项 | 值 |
| --- | --- |
| 上游控制面 | `CONTROLPLANE_BASE_URL`，默认 `http://localhost:8081`（**仅服务端可读**） |
| 数据面（会话/技能） | `NEXT_PUBLIC_API_BASE_URL`，默认 `http://localhost:8080` |
| 浏览器访问 | 只访问同源 `/api/**`，由 Next BFF 转发到 8081 |

**硬性约束**：浏览器与 BFF 都**不得**访问 `/internal/**`。该组接口用 `X-Internal-Token`
做服务间鉴权，一旦下发到前端等于泄露内部凭证。

### 0.2 认证与权限

- 所有 `/api/**` 接口都带 `Authorization: Bearer <jwt>`，沿用 `src/lib/bff-auth.ts` 的 `bearerHeaders(request)`。
- 用户身份一律从 Token 解析，**接口不接受 `userId` 入参**（防越权）。

| 路径前缀 | 要求 | 失败响应 |
| --- | --- | --- |
| `/api/admin/**` | 已登录 + 角色 `ADMIN` | 未登录 `401 UNAUTHENTICATED`；非管理员 `403 FORBIDDEN` |
| `/api/experts/**`、`/api/knowledge/**` | 仅需登录 | `401 UNAUTHENTICATED` |

### 0.3 时间、ID 与空值约定

- **时间**：全部为 epoch **毫秒**（`number`）。`indexedAt` / `startedAt` / `finishedAt` 可能为 `null`。
- **ID**：不透明字符串，带前缀（`kb_` / `doc_` / `ver_` / `job_` / `ck_` / `cit_` / `exp_` / `u_`），**不要解析**。
- **空串 vs null**：
  - `CitationView.expertId` / `expertName` / `toolCallId` 基础模式下是 `""`，不是 `null`；
  - `CitationView.finalRank`、`CitationView.citationId` 可能是 `null`；
  - `CitationDetail.chunk` / `parent` 可能是 `null`。

### 0.4 统一错误模型

所有错误都是同一形状（`aoteman-common` 的 `ApiError`），前端只需一套解析逻辑：

```json
{
  "code": "KB_NOT_FOUND",
  "message": "知识库不存在: kb_abc",
  "timestamp": 1762345678901
}
```

- 分支判断**只用 `code`**；`message` 已是中文，可直接展示。
- Spring 自带错误（404/405 等）统一映射为 `REQUEST_ERROR`；请求体 JSON 解析失败为 `INVALID_REQUEST_BODY`；兜底为 `INTERNAL_ERROR`。

### 0.5 状态枚举（前端仅需这 8 组）

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `knowledgeBase.status` | `ACTIVE` / `DELETED` | 新建即 `ACTIVE`；删除为软删 |
| `document.status` | `PENDING` / `READY` / `FAILED` | 列表接口已排除 `DELETED` |
| `version.status` | `PENDING` / `READY` / `FAILED` | `READY` 才对外可召回 |
| `job.status` | `PENDING` / `RUNNING` / `SUCCEEDED` / `FAILED` | 终态 = `SUCCEEDED` / `FAILED` |
| `job.stage` | `PARSE` / `CHUNK` / `EMBED` / `INDEX` | 对应入库四段进度 |
| `expert.status` | `DRAFT` / `ACTIVE` / `DISABLED` | `DELETED` 只出现在库内，接口不接受 |
| `chunkStrategy` | `AUTO` / `TOC` / `FIXED` | 大小写不敏感，服务端会转大写 |
| `chunkType` | `CHILD` / `PARENT` | `TOC` 策略才有 `PARENT` |

### 0.6 分页规则

- **只有切片接口分页**，其余列表接口返回全量数组。
- 切片分页：`page` 从 **1** 开始；`size` 默认 20、上限 **200**；超出上限是**夹取**（不报错），
  所以分页器必须用**响应里回传的 `page` / `size`** 渲染，不能直接用请求参数。

## 2. 管理端 · 知识库

### 2.1 新建知识库

```http
POST /api/admin/knowledge/bases
Content-Type: application/json
```

```json
{
  "name": "行政制度",
  "description": "公司行政类制度文件",
  "chunkStrategy": "AUTO",
  "configJson": null
}
```

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `name` | 是 | 去空格后非空，≤ 100 字符 |
| `description` | 否 | ≤ 500 字符 |
| `chunkStrategy` | 否 | `AUTO`（默认）/ `TOC` / `FIXED` |
| `configJson` | 否 | 原样存库的 JSON **字符串**，空串等价 `null` |

**响应 201**：

```json
{
  "kbId": "kb_3f7c1a2b9d8e4f60a1b2c3d4",
  "name": "行政制度",
  "description": "公司行政类制度文件",
  "status": "ACTIVE",
  "embeddingModel": "qwen3-embedding",
  "embeddingDim": 1024,
  "collectionName": "aoteman_knowledge",
  "chunkStrategy": "AUTO",
  "configJson": null,
  "createdAt": 1762345678901,
  "updatedAt": 1762345678901
}
```

> `embeddingModel` / `embeddingDim` / `collectionName` 由服务端配置决定，**前端只读展示**，提交了也会被忽略。

**错误**：`400 INVALID_KB`（名称为空/超长、策略非法）。

### 2.2 知识库列表

```http
GET /api/admin/knowledge/bases
```

**响应 200**：`KnowledgeBaseView[]`，按创建时间倒序，**无分页**。

> ⚠️ **实现细节**：当前 `listBases` 未过滤软删行，响应里可能包含 `status = "DELETED"` 的记录。
> 前端列表必须自行 `filter(item => item.status !== "DELETED")`，否则会出现"删了还在"的幽灵条目。

### 2.3 详情 / 修改 / 删除

```http
GET    /api/admin/knowledge/bases/{kbId}     # 200 KnowledgeBaseView
PATCH  /api/admin/knowledge/bases/{kbId}     # 200 KnowledgeBaseView
DELETE /api/admin/knowledge/bases/{kbId}     # 204 无响应体
```

`PATCH` 是**部分更新**，但四个字段的空值语义不一致，务必注意：

| 字段 | 传 `null` / 不传 | 传 `""` |
| --- | --- | --- |
| `name` | 保持原值 | 报错 `INVALID_KB`（名称不能为空） |
| `description` | 保持原值 | 清空描述 |
| `chunkStrategy` | 保持原值 | 报错 `INVALID_KB` |
| `configJson` | **清空** | 清空 |

> 删除为软删：之后再 `GET` 该 `kbId` 一律 `404 KB_NOT_FOUND`；
> 该库下文档、切片、引用**不做级联删除**，引用快照仍可查（见 §6.2）。

### 2.4 知识库授权

```http
GET /api/admin/knowledge/bases/{kbId}/grants
```

```json
{ "userIds": ["u_1", "u_2"] }
```

```http
PUT /api/admin/knowledge/bases/{kbId}/grants
Content-Type: application/json

{ "userIds": ["u_1", "u_3"] }
```

- **全量替换语义**：请求里没有的 `userId` 会被收回；空数组 = 收回全部。
- `userIds` 会去空格、去重、去空；顺序不保证。
- 返回替换后的最新 `{ "userIds": [...] }`。
- 选择器数据源：`GET /api/admin/users`（见 §7）。

## 3. 管理端 · 文档与入库

### 3.1 上传文档（唯一入口，仅支持 `.docx`）

```http
POST /api/admin/knowledge/bases/{kbId}/documents
Content-Type: multipart/form-data
```

| 表单字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 仅 `.docx` |
| `strategy` | 否 | `AUTO` / `TOC` / `FIXED`，缺省用知识库配置 |
| `replaceDocumentId` | 否 | 覆盖上传：指定被替换的文档 ID |

**响应 202**：

```json
{
  "documentId": "doc_9a8b7c6d5e4f3a2b1c0d9e8f",
  "versionId": "ver_1a2b3c4d5e6f7a8b9c0d1e2f",
  "jobId": "job_5f4e3d2c1b0a9f8e7d6c5b4a",
  "duplicate": false
}
```

- **`duplicate = true`**：同库同 SHA-256 已存在，**没有**新建版本与任务 → 前端**不要**启动新的入库轮询，
  直接提示"该文件已存在"，并提供跳转到已有文档的入口。
- 上传成功后立刻用 `jobId` 轮询任务（§3.6）。

**错误**：

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `UNSUPPORTED_FILE_TYPE` | 非 `.docx`（`.doc` / `.docm` / `.pdf` 均拒绝） |
| 400 | `INVALID_DOCX` | 后缀是 docx 但 ZIP / `[Content_Types].xml` 结构非法 |
| 413 | `FILE_TOO_LARGE` | 超过单文件大小上限 |
| 413 | `TEXT_TOO_LARGE` | 解压体积 / 提取文本超限 |
| 400 | `NO_EXTRACTED_TEXT` | 没有可提取文本 |
| 404 | `KB_NOT_FOUND` | 知识库不存在或已删除 |
| 400 | `INVALID_KB` | 策略非法 / 知识库非 `ACTIVE` |

### 3.5 切片分页

```http
GET /api/admin/knowledge/documents/{documentId}/chunks?versionId=&type=CHILD&page=1&size=20
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `versionId` | 空 = 最新版本 | 历史版本预览必须显式传 |
| `type` | `CHILD` | `CHILD` / `PARENT` |
| `page` | 1 | 从 1 开始，<1 会被夹到 1 |
| `size` | 20 | ≤0 取 20，>200 夹到 200 |

**响应 200**：

```json
{
  "items": [{
    "chunkId": "ck_1f2e3d4c5b6a79880a1b2c3d",

    "pageTo": 0

  "size": 20,
  "total": 87
}
```

### 3.6 入库任务轮询

```http
GET /api/admin/knowledge/jobs/{jobId}
```

```json
{
  "jobId": "job_5f4e3d2c1b0a9f8e7d6c5b4a",
  "kbId": "kb_3f7c1a2b9d8e4f60a1b2c3d4",
  "documentId": "doc_9a8b7c6d5e4f3a2b1c0d9e8f",
  "versionId": "ver_1a2b3c4d5e6f7a8b9c0d1e2f",
  "status": "RUNNING",
  "stage": "EMBED",
  "progress": 55,
  "attempt": 1,
  "maxAttempts": 3,
  "errorCode": "",
  "errorMessage": "",
  "startedAt": 1762345678901,
  "finishedAt": null,
  "createdAt": 1762345678901,
  "updatedAt": 1762345678901
}
```

- `progress` 是 0–100 的整数，按阶段给出：`PARSE` 5 → `CHUNK` 30 → `EMBED` 55 → `INDEX` 80 → 完成 100。
- **终态**：`SUCCEEDED` / `FAILED`，到达终态立即停止轮询。
- `attempt` / `maxAttempts`：自动重试最多 3 次，失败可提示"已重试 N/3"。

### 3.7 重试入库

```http
POST /api/admin/knowledge/documents/{documentId}/retry
```

**响应 202**：`JobView`（同上形状，`status = "PENDING"`）。

- 重试固定针对**最新版本**重建任务，不能指定历史版本。
- 队列满时任务保持 `PENDING`，由调度器补偿 —— 前端继续轮询即可，不要判成失败。

## 4. 管理端 · 专家

### 4.1 新建专家

```http
POST /api/admin/experts
Content-Type: application/json

{
  "name": "法务专家",
  "description": "合同与合规审查",
  "avatarUrl": "",
  "welcomeMessage": "你好，我可以帮你审合同。",
  "systemPrompt": "你是一名资深法务……",
  "status": "DRAFT"
}
```

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `name` | 是 | 非空 |
| `description` | 否 | — |
| `avatarUrl` | 否 | 图片 URL 字符串（前端自行处理占位） |
| `welcomeMessage` | 否 | 问答页开场白 |
| `systemPrompt` | 是 | **≤ 6000 字符** |
| `status` | 否 | 默认 `DRAFT`；仅 `DRAFT` / `ACTIVE` / `DISABLED` |

**响应 201**：`ExpertAdminResponse`（**唯一会下发 `systemPrompt` 的接口组**）：

```json
{
  "expertId": "exp_7a6b5c4d3e2f1a0b9c8d7e6f",
  "name": "法务专家",
  "description": "合同与合规审查",
  "avatarUrl": "",
  "welcomeMessage": "你好，我可以帮你审合同。",
  "systemPrompt": "你是一名资深法务……",
  "status": "DRAFT",
  "kbIds": [],
  "createdAt": 1762345678901,
  "updatedAt": 1762345678901
}
```

**错误**：`400 INVALID_EXPERT`、`400 INVALID_EXPERT_STATUS`、`400 PROMPT_TOO_LONG`。

### 4.2 列表 / 详情

```http
GET /api/admin/experts              # 200 ExpertAdminResponse[]（全量，无分页）
GET /api/admin/experts/{expertId}   # 200 ExpertAdminResponse
```

- 列表包含所有未删除专家（`DRAFT` / `ACTIVE` / `DISABLED`）。
- 不存在 / 已删除 → `404 EXPERT_NOT_FOUND`。

### 4.3 更新专家（⚠️ 全量覆盖）

```http
PATCH /api/admin/experts/{expertId}
```

**语义是整体替换，不是补丁**：未提交的字段按空值写入。编辑页必须提交**完整表单**
（`name` / `description` / `avatarUrl` / `welcomeMessage` / `systemPrompt` / `status` 六项全传），
否则会出现"改个名字把提示词清空了"。

- `status` 传 `null` 时保持原状态；
- `status = "DELETED"` 会被拒绝（`400 INVALID_EXPERT_STATUS`），删除只能走 `DELETE`。

### 4.4 删除专家

```http
DELETE /api/admin/experts/{expertId}   # 204
```

软删；之后用户端立即不可见，管理端详情返回 `404 EXPERT_NOT_FOUND`。

### 4.5 绑定知识库

```http
GET /api/admin/experts/{expertId}/knowledge-bases
```

```json
{ "kbIds": ["kb_3f7c1a2b9d8e4f60a1b2c3d4"] }
```

```http
PUT /api/admin/experts/{expertId}/knowledge-bases

{ "kbIds": ["kb_3f7c...", "kb_9a8b..."] }
```

- **全量替换**；空数组 = 解绑全部。
- 只接受 `ACTIVE` 知识库；含非法 / 已删除 `kbId` → `400 INVALID_EXPERT`。
- 返回替换后**实际生效**的 `kbIds`（服务端会用它覆盖响应）。

### 4.6 专家授权

```http
GET /api/admin/experts/{expertId}/grants    # { "userIds": [...] }
PUT /api/admin/experts/{expertId}/grants    # 全量替换，返回最新 { "userIds": [...] }
```

- 空数组 = 收回全部授权。

  （间接可达），即使该用户对知识库没有直接授权。

## 6. 用户端 · 检索与引用

### 6.1 手动检索

```http
POST /api/knowledge/search
Content-Type: application/json

{
  "sessionId": "s_123",
  "toolCallId": "call_1",
  "expertIds": [],
  "query": "年假怎么申请",
  "topK": 5
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `sessionId` | 否 | 传了才会落库引用 |
| `toolCallId` | 否 | 同上，用于引用幂等键 |
| `expertIds` | 否 | 为空 = 基础模式（按用户直接授权检索） |
| `query` | 是 | 非空白，否则 `400 INVALID_QUERY` |
| `topK` | 否 | 建议 3–8 |

**响应 200**：

```json
{
  "context": "[K1] 《员工手册》 | 知识库：行政制度 | 第三章 > 3.2\n……",
  "citations": [{
    "ref": "K1",
    "finalRank": 1,
    "citationId": "cit_1a2b3c4d5e6f7a8b9c0d1e2f",
    "toolCallId": "call_1",
    "expertId": "",
    "expertName": "",
    "kbId": "kb_3f7c1a2b9d8e4f60a1b2c3d4",
    "kbName": "行政制度",
    "documentId": "doc_9a8b7c6d5e4f3a2b1c0d9e8f",
    "documentTitle": "员工手册",
    "fileName": "员工手册.docx",
    "versionId": "ver_1a2b3c4d5e6f7a8b9c0d1e2f",
    "chunkId": "ck_1f2e3d4c5b6a79880a1b2c3d",
    "parentChunkId": "ck_p1f2e3d4c5b6a79880a1b2c",
    "headingPath": "第三章 > 3.2 年假",
    "pageFrom": 0,
    "pageTo": 0,
    "chunkOrdinal": 12,
    "chunkTotal": 87,
    "snippet": "员工累计工作满一年……",
    "vectorScore": 0.83,
    "rerankScore": 0.91
  }],
  "degraded": false
}
```

**关键语义（前端必须理解）**：

1. `citationId` 只有在 `sessionId` 与 `toolCallId` 都非空时才非 `null`；
   否则是**不可点击的草稿**，`citationId = null`，不能打开详情抽屉。
2. `expertIds` 只影响**检索范围**（多专家取并集），**不会触发专家子 Agent 编排**。
   真正的"选专家问答"走聊天接口（`/api/conversations/**` + 专家选择），
   本接口定位是**调试 / 手动检索 / 引用预览**。
3. `degraded = true` 表示 rerank 失败已回退向量排序，前端应显示"排序降级"提示。
4. `finalRank` 为 `null` 表示尚未最终排序（专家子 Agent 草稿阶段），文案上要从"第 N 条"降级为"参考 N"。

**错误**：`403 NO_ACCESSIBLE_KB`（既无直接授权、所选专家也没绑库）、`400 INVALID_QUERY`。

### 6.2 引用详情

```http
GET /api/knowledge/citations/{citationId}
```

```json
{
  "citation": { "...": "CitationView，字段同 §6.1" },
  "chunk": {
    "chunkId": "ck_1f2e3d4c5b6a79880a1b2c3d",
    "content": "员工累计工作满一年……",
    "prevChunkId": "ck_0f2e3d4c5b6a79880a1b2c3d",
    "nextChunkId": "ck_2f2e3d4c5b6a79880a1b2c3d"
  },
  "parent": {
    "chunkId": "ck_p1f2e3d4c5b6a79880a1b2c",
    "content": "第三章 假期管理……",
    "headingPath": "第三章 > 3.2 年假"
  },
  "document": {
    "documentId": "doc_9a8b7c6d5e4f3a2b1c0d9e8f",
    "title": "员工手册",
    "fileName": "员工手册.docx",
    "fileExt": "docx"
  },
  "accessRevoked": false,
  "documentDeleted": false
}
```

**权限与降级规则**：

| 情形 | 行为 |
| --- | --- |
| 非本人且非 ADMIN | **404 `CITATION_NOT_FOUND`**（不泄露存在性） |
| 授权被回收 | 200，`accessRevoked = true`，`chunk` / `parent` 为 `null`，快照字段照常 |
| 文档已软删 | 200，`documentDeleted = true`，`chunk` / `parent` 为 `null` |
| `prevChunkId` / `nextChunkId` | 空串表示没有相邻块（不是 `null`） |
| 固定切片策略 | `parent = null`（没有父块） |

> 抽屉里"上一段/下一段"按钮以 `prevChunkId` / `nextChunkId` 是否为空串判断可用性。

### 6.3 引用原文下载

```http
GET /api/knowledge/citations/{citationId}/document
```

- **200**：二进制流，`Content-Disposition: attachment; filename*=UTF-8''...`，
  `Content-Type` 为 docx 的 MIME。
- **410 `DOCUMENT_UNAVAILABLE`**：授权回收或文档删除（快照还在，原文不给）。
- **404 `DOCUMENT_NOT_FOUND`**：版本行或物理文件缺失。
- **404 `CITATION_NOT_FOUND`**：非本人引用。

> BFF 必须**流式透传** `res.body`，不要 `arrayBuffer()`（大文件会爆内存）。
> 下载固定使用**引用行里的 `versionId`**，不会切到文档最新版本 —— 这是审计语义，不要"优化"。

### 6.4 引用邻块（详情抽屉的上一块 / 下一块）

```http
GET /api/knowledge/citations/{citationId}/chunks/{chunkId}
```

```json
{
  "chunkId": "ck_2f2e3d4c5b6a79880a1b2c3d",
  "content": "员工累计工作满一年……",
  "prevChunkId": "ck_1f2e3d4c5b6a79880a1b2c3d",
  "nextChunkId": "ck_3f2e3d4c5b6a79880a1b2c3d"
}
```

- 只允许读取**同一引用、同一文档版本内**的 `CHILD` 块；跨版本 / 非 CHILD / 越权探测统一 404；
- 空串表示没有相邻块（不是 `null`）。

| 情形 | 响应 |
| --- | --- |
| 正常 | 200 `ChunkView` |
| 授权被回收 / 文档已删除 | 410 `DOCUMENT_UNAVAILABLE` |
| 引用非本人且非 ADMIN | 404 `CITATION_NOT_FOUND` |
| 切片不存在或不属于该引用 | 404 `CHUNK_NOT_FOUND` |

> 前端不要用管理端切片分页接口（`/api/admin/**`，需 ADMIN）来实现「上一块/下一块」。

## 8. 前端禁止调用的接口

| 路径 | 原因 |
| --- | --- |
| `POST /internal/experts/resolve` | 服务间接口，需 `X-Internal-Token`，仅供 agent 数据面解析专家 |
| `POST /internal/knowledge/search` | 同上；专家子 Agent 内部的单专家检索 |
| `POST /internal/knowledge/citations/finalize`（后续 Task 11B） | 同上；引用落库由 agent 侧统一提交 |

`/internal/**` 在 token 未配置时是 **fail-closed 全 401**，并且浏览器一旦能调到它，
就说明内部凭证已经泄露到前端，属于安全事故。

## 9. 对接坑位清单（按踩坑概率排序）

1. **专家列表不是"合并知识点"**：每个专家带自己的 `kbIds`，后端刻意不提供
   `mergedKbIds` / `totalPromptChars`。前端多选专家时不要自己求并集去展示"共 N 个库"，
   要按专家分组展示。
2. **专家 `PATCH` 是全量覆盖**：编辑页必须提交完整表单，否则会清空未提交字段。
3. **知识库 `PATCH` 的 `configJson` 传 `null` = 清空**，而 `name` / `description` 传 `null` = 保持原值。
4. **知识库列表含 `DELETED`**：前端必须过滤（见 §2.2）。
5. **上传 `duplicate = true` 时没有新任务**：不要拿 `jobId` 去轮询（会 404）。
6. **multipart 不要手动设 `Content-Type`**，让 `fetch` 自动带 boundary。
7. **切片 `size > 200` 会被夹取**：分页器用响应回传的 `size`，不要用请求参数。
8. **`citationId` 可能为 `null`**：草稿引用不可点击，UI 要区分"可溯源"与"仅参考"。
9. **`finalRank` 可能为 `null`**：排序文案要有兜底。
10. **下载用引用行的 `versionId`**：不要改成"最新版本"。
11. **`/api/experts/{id}` 对未授权统一 403**，不要据此区分"不存在"与"没权限"。
12. **时间都是毫秒数**，直接 `new Date(ms)`；不要当秒处理。
