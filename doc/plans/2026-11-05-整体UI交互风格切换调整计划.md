## 2. 三项决策（已确认 · 2026-11-05）

> 用户已拍板，以下为最终口径，后续实施一律以此为准。

| # | 决策项 | 最终结论 |
| --- | --- | --- |
| 1 | 主题策略 | **A 深色优先 + 浅色等价适配**：同一套 token 结构，浅色只换值与环境光强度 |
| 2 | 主强调色 | **原型紫 `#7C5CFF`**（深色 `#7C5CFF` / 浅色压到 `#5B3FE0` 保对比度）；青绿降级为「在线/成功」语义色 |
| 3 | 产物画布（04） | **本期做**；第一阶段只支持 **Markdown + PPTX**，只做「看 + 下载」 |

> 下面三小节保留的是当时的三方案对比，作为决策依据留档。

### 决策 1：主题策略

| 方案 | 内容 | 成本 | 结论 |
| --- | --- | --- | --- |
| **A（推荐）** | **深色优先 + 浅色等价适配**：以原型深色为设计基准，浅色用同一套 token 结构反向映射（亮度分层改成 4 档浅灰，环境光降到 4%） | +30% token 工作量 | ✅ 推荐 |
| B | 只做深色，移除 `ThemeToggle` | -30% | ❌ 已有主题切换，直接删是功能倒退 |
| C | 保持浅色为主，只借用原型的层次手法 | 0 | ❌ 达不到「立体感」目标 |

**推荐 A 的理由**：`next-themes` + `ThemeToggle` 已在线上，用户已有偏好；且「亮度分层」在浅色下同样成立（浅灰 4 档差 2~3 个 L 值），不是深色专属手法。

### 决策 2：主强调色

| 方案 | 内容 | 结论 |
| --- | --- | --- |
| **A（推荐）** | 采用原型紫 `#7C5CFF` 作为唯一主强调色（深色 `#7C5CFF` / 浅色压到 `#5B3FE0` 保证对比度 ≥ 4.5:1）；青绿降级为「在线/成功」语义色 | ✅ 推荐 |
| B | 保留青绿 `oklch(0.5 0.09 195)` 作为主色，只改层次与动效 | 风险最低，但「换了皮没换气质」 |

**推荐 A 的理由**：用户明确想要原型那种质感；且 `--success` 本身已是绿色语义，青绿与「成功」语义重叠，作为主色反而模糊。

### 决策 3：产物画布（04）是否本期做

**最终：做，但只做只读能力。** 三态骨架（chat / split / canvas）+ Markdown 完整渲染 + PPTX 发现/下载，**不做**编辑、版本、自然语言改、导出任务（这些缺后端）。PPTX 还缺一个后端白名单放行，见 §P6.1。

#### T1.1 重写 token 层（`src/app/globals.css`）

**原则：保留 shadcn 变量名（`--background` / `--card` / `--primary` …）不变，只换值与新增语义层**，这样 `components/ui/*` 的 60+ 个组件不用逐个改。

新增（与 `tokens.css` 一一对应）：

| 失败态 | 后端 415 / 404 时，面板提示「当前服务端未开启该类型预览」+ 下载按钮保持可用 |

### 8.5 本地静态预览（8080 / 8081 未启动时）

前端自带演示数据，后端全停也能走查。前提：在 `aoteman-web` 下跑 `npm run dev`（默认 3000）。

| 页面 | 地址 |
| --- | --- |
| 问答工作台 | `http://localhost:3000/?preview=1` |
| 知识库列表 | `http://localhost:3000/admin/knowledge?preview=1` |
| 知识库详情 | `http://localhost:3000/admin/knowledge/kb_hr?preview=1` |
| 专家模型列表 | `http://localhost:3000/admin/experts?preview=1` |
| 专家新建 / 编辑 | `http://localhost:3000/admin/experts/new?preview=1`、`http://localhost:3000/admin/experts/exp_legal?preview=1` |
| 技能管理 | `http://localhost:3000/admin/skills?preview=1` |
| 权限规则 | `http://localhost:3000/admin/permissions?preview=1` |

行为说明：

- 首次带 `?preview=1` 进入会写 8 小时有效的 `aoteman_dev_preview=1` Cookie（`src/lib/dev-preview.ts`）；
  之后 F5、新标签页直接打开 `/admin/**` 都不会掉回 `/login`，页内「退出预览」会立刻清掉它。
- 该 Cookie 只是开发期登录守卫的放行标记，**不是鉴权凭证**：middleware 里带
  `NODE_ENV !== 'production'` 判断，`next build` 后这条旁路不存在，演示数据逻辑也一并关闭。
- 不带 `?preview=1`、也没有预览 Cookie 与登录态时，仍按原逻辑 307 跳 `/login`。
- 预览期间页面右上角显示「预览模式」/「静态预览」标记，接口错误（控制面未启动的 ECONNREFUSED）属预期。
