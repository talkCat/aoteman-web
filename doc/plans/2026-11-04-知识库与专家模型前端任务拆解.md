### 1.2 明确不做（v1 边界）

- 组织 / 团队 / 角色授权：后端 v1 未建模，UI 不出现入口。
- PDF / `.doc` / `.docm`：前端**主动拦截**并给准确文案，不做「即将支持」灰按钮。
- 批量上传 / 文件夹上传 / 拖拽排序。
- **技能与 MCP 的真实配置**：后端能力未实现，只做只读占位区（见 F-08），不做假开关、不发请求。
- 专家之间的相互调用 / 可视化编排画布。
- 提示词变量、模板市场、检索评测面板、运营大屏。
- 引用高亮原文（DOCX 渲染器），v1 只到「快照 + 块序号」。
- **不新增任何 npm 依赖**（含 MSW、表单 schema 生成器、图表库、动画库）。

### 1.3 技术硬约束

1. **技术栈固定**：Next 15 App Router + React 19 + TypeScript + Tailwind 4 + Radix/shadcn + lucide + sonner。复用 `src/components/ui/*`，不要另起一套。
2. **浏览器只访问同源 `/api/**`**。`CONTROLPLANE_BASE_URL`（默认 `http://localhost:8081`）只在服务端读，**禁止**加 `NEXT_PUBLIC_` 前缀。
3. 所有管理端 BFF 路由必须 `await requireAdmin(request)` 兜底（`src/lib/current-user.ts`），不依赖页面守卫；401/403 用 `currentUserErrorResponse(error)` 统一转换。
4. `multipart/form-data` **不要手写 `Content-Type`**，让 `fetch` 带 boundary；下载用 `res.body` 透传，不 `arrayBuffer()`。
5. **不新增颜色令牌**。状态一律「2px 圆点 + 文字」，颜色只做辅助；列表用行式布局，不用卡片墙。
6. **提示词永不出管理端**：用户端接口与类型里不出现 `systemPrompt`。管理端类型 `AdminExpertDetail` 才允许有该字段。
7. **不允许假入口**：未实现能力用 `disabled` + 说明文案，禁止 `onClick={() => {}}`、禁止「敬请期待」按钮。
8. 所有新增文件 **UTF-8 无 BOM**；中文文案用中文标点，与现有页面一致。
9. 凡属框架 API（Next Route Handler / Radix `Sheet` `Command` / react-markdown `remarkPlugins`），**先查官方文档再写**（AGENTS.md 第一节第 ② 类）。
10. **不改 `src/app/page.tsx` 的 SSE 状态机**，只做「加字段 + 抽组件 + 加渲染」；改动后必须用 Chrome DevTools MCP 实测回归（见 §6.3）。

## 2. 接口契约

> 前端按本节写类型与 mock。后端可微调字段名，但**改动必须同步本节**（在同一个 PR 里改）。

### 2.1 通用约定

```ts
export type Page<T> = { items: T[]; page: number; size: number; total: number };

export type ApiError = { code: string; message: string; traceId?: string };
```

- BFF 新路由统一返回 `ApiError`；BFF 原样透传 status；前端按 `code` 分支，**不按 message 字符串匹配**。
- 例外：现有 `currentUserErrorResponse()` 仍可能返回 `{ error: string }`。`lib/controlplane.ts#toApiError()` 必须兼容 `{ code, message }` 与 `{ error }` 两种形状并归一化（缺失 code 时用 `HTTP_${status}` 兜底），页面不直接读原始 JSON。
- 时间一律 epoch millis（`number`），格式化用现有 `date-fns`。
- `ordinal` 从 1 开始；`pageFrom/pageTo` 为 0 表示「无页码」（DOCX 恒为 0）。

### 2.3 专家（v2：独立模块 + 资源绑定）

**定义**：专家 = 名称/描述/欢迎语 + 系统提示词 + 资源绑定（知识库 / 技能 / MCP）+ 用户授权 + 发布状态。

- **知识库**：v1 可用，是专家的资源，不是知识库的属性。
- **技能 / MCP**：v1 后端未实现，接口返回 `enabled:false` 与空数组，前端只渲染只读占位区。
- 任何「在知识库里选专家」的入口都是错的。

### 2.4 问答侧

提交（现有事件格式，只加一个字段）：


回显（服务端解析后补写，前端只读）：

```json

    "text": "年假怎么申请",
```

### 2.7 专家运行事件（2026-11-04 已定稿）

一轮专家问答有两条事件流，随 SSE `seq` 顺序到达；历史回放与实时同构。

```ts
export type ExpertRunStatus = 'QUEUED' | 'RUNNING' | 'DONE' | 'FAILED' | 'CANCELLED' | 'SKIPPED';

export interface ExpertRunItem {
  expertId: string;
  expertName: string;
  order: number;            // 1..n，等于用户选择顺序
  status: ExpertRunStatus;
}

/** agent.expert_runs —— 批次级 */
export interface AgentExpertRunsEvent {
  type: 'agent.expert_runs';
  runId: string;            // "xrun_<turnId>"
  phase: 'STARTED' | 'FINISHED';
  mode: 'PARALLEL';
  parallelism: number;
  experts: ExpertRunItem[]; // STARTED 时全为 QUEUED
  // 仅 phase = FINISHED 时有值
  degraded?: boolean;
  succeededCount?: number;
  failedCount?: number;
}

/** agent.expert_run —— 单专家级 */
export interface AgentExpertRunEvent {
  type: 'agent.expert_run';
  runId: string;
  expertId: string;
  expertName: string;
  order: number;
  status: ExpertRunStatus;
  startedAt: number | null;   // epoch ms
  finishedAt: number | null;
  durationMs: number | null;
  errorCode: string | null;   // EXPERT_TIMEOUT / EXPERT_MODEL_ERROR / EXPERT_EMPTY_OUTPUT / EXPERT_CAPABILITY_MISMATCH
  errorMessage: string | null;// 只放 title，不直接长文展示
  truncated: boolean;         // 专家结论被截断
}
```

渲染规则：

1. 按 `runId` 聚合**一条**状态条；组内按 `order` 升序，**不按到达顺序**（并行完成顺序随机）。
2. `status` 变化即覆盖同一 `expertId` 的旧值，幂等，不累加出重复 chip。
3. `phase=FINISHED` 后状态条定型；`degraded=true` 时在回答正文上方加提示条。
4. `succeededCount === 0` 仍展示最终回答，但不渲染参考资料区。
5. `errorCode → 中文文案` 的映射集中在 `src/lib/expert-run.ts`，组件内不散落字符串。
6. 没有 `runId`（基础问答）不渲染状态条。
