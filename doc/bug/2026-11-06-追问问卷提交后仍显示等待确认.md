# 追问问卷提交后工具卡仍停在「等待确认」

- 日期：2026-11-06
- 模块：`src/app/page.tsx`（`submitFollowupQuestionnaire`）
- 状态：已修复并实测
- 关联：`doc/design/2026-11-06-会话流与重复工具调用-服务端接口需求.md`、`doc/bug/2026-11-06-会话流串台与工具卡状态回退.md`

---

## 1. 现象

追问问卷（`ask_followup_questions`）答完并成功提交后：

1. 卡片头部状态仍然是「等待确认」（橙色悬挂态），而卡片正文已经显示「已确认：1. … 2. …」；
2. 该轮的过程区折叠标题也一直显示「等待确认」，不会变成「已完成思考」；
3. 下一轮已经开始（新一轮追问卡/正文正常出现），说明服务端确实受理了答案。

## 2. 复现与证据

在 `http://localhost:3000` 新建会话，发送「帮我做一份公司年会方案」，页面上会出现追问问卷卡。

会话 `1793964079459-86huzj475` 的落盘事件（`GET /api/sessions/{id}/events?after=0`）：

```
seq=73  agent.tool_use      name=ask_followup_questions  id=call_7ec3807fa07f4fce84d80557
seq=76  agent.tool_result   name=ask_followup_questions  id=call_7ec3807fa07f4fce84d80557  state=RUNNING
seq=78  agent.tool_suspended name=ask_followup_questions id=call_7ec3807fa07f4fce84d80557  state=suspended
seq=80  session.requires_action
seq=82  user.tool_result    name=ask_followup_questions
seq=83.. 新一轮（span.model_request_start / agent.tool_use 新 toolCallId）
```

对比「工具确认」路径（`delete_file`）：确认受理后服务端会补一条终态
`agent.tool_result`（seq=38，`state=ERROR/SUCCESS`），卡片因此能收尾。

`ask_followup_questions` 的结果由**用户答案**提供（`user.tool_result`），服务端不会
再补发 `agent.tool_result`，所以前端收不到任何终态帧。

## 3. 根因

`submitFollowupQuestionnaire` 在服务端受理成功后只做了三件事：
清空问卷、写入可读答案、推进本地轮次，**没有**把该 `toolCallId` 对应的工具卡从
`suspended` 收尾成终态。

而 `ProcessCard` 的标题由 `hasSuspendedTool` 决定、`ToolCard` 的状态标签由
`tool.status` 决定，两者都直接读工具卡状态，于是永远停在「等待确认」。

## 4. 方案

前端本地收尾（不改服务端协议）：

- 受理成功（`result.accepted === true`）后，把该 `toolCallId` 的工具卡标记为 `success`；
- 幂等命中（`duplicateReason`，服务端此前已处理）同样标记为 `success`，因为答案确实已生效；
- 不动 `finishedAt`，避免把「用户思考时间」算进工具耗时；
- 真失败不标记，保留重试能力（与 `submitToolConfirmation` 的处理保持一致）。

## 5. 验证

1. `node node_modules/typescript/bin/tsc --noEmit` → 通过；
2. `node node_modules/next/dist/bin/next lint` → 无告警；
3. `node node_modules/next/dist/bin/next build` → 通过；
4. 浏览器实测（同一会话第 6 轮追问）：
   - 提交答答案后卡片状态变为「已完成」，过程区标题变为「已完成思考」；
   - 新一轮追问卡正常出现，可继续作答；
   - Console 无报错。

## 6. 服务端交付后的对接补充（2026-11-06）

服务端确认：追问结果由用户答案提供（`user.tool_result`），**不会**再补 `agent.tool_result`。
因此把「本地提交成功后手动收尾」升级为「以 `user.tool_result` 为唯一权威终态」，实时收流与
SSE 回放共用同一条链路：

- `useSSEStream` 订阅 `user.tool_result`，取出 `payload.tool_use_id`，回调
  `onUserToolResult(toolCallId, toolName)`；
- 页面 `handleUserToolResult` 把对应工具卡置为 `success`，并写入
  `settledToolCallIdsRef`；
- 幂等命中（`DUPLICATE_TOOL_RESULT`）走同一收尾逻辑，不提示、不追加答案、不推进轮次；
- 历史回放时，迟到/重放的 `session.requires_action` 会先查 `settledToolCallIdsRef`，
  终态已存在就不再生成可点击的追问卡。

这样即使「提交成功但本地先收到结果帧」，或「刷新后纯回放」，卡片都不会再停在「等待确认」。
