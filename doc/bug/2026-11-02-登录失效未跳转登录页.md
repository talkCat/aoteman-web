# 登录态校验失败后未跳转登录页

- 日期：2026-11-02
- 页面：`/`（智能体工作台）
- 状态：已修复（前端）

## 现象

1. 浏览器中已存在 `aoteman_token` Cookie（本地调试留下的 admin JWT）。
2. 打开 `http://localhost:3000/`，首页正常渲染，并进入匿名工作台（顶栏「未连接」、侧栏为空、输入框可用），没有跳转 `/login`。
3. Console 持续出现 502，SSE 报错，页面实际不可用。

期望：登录态确认失败（未登录 / token 失效 / 身份服务不可达）时，顶层页面应直接回到登录页，而不是静默降级为匿名用户。

## 取证（Chrome DevTools MCP）

- `GET /api/auth/me` → `502`，响应体
  `{"code":"UPSTREAM_UNAVAILABLE","message":"服务暂时不可用，请稍后重试"}`；
  请求头 Cookie 中携带 `aoteman_token=...`。
- 同页 `GET /api/sessions?userId=anonymous&limit=50`、`GET /api/artifacts?...` 均返回 `502`；
  `GET /api/sessions/.../events/stream` 挂起后前端报 `SSE Error`。
- 页面快照（take_snapshot）：顶栏显示「未连接」，输入框可输入 —— 确实以 anonymous 身份留在工作台。
- 服务端探测：`http://localhost:8081/api/user/me` 请求超时（控制面未启动），这是本次 502 的直接原因。
- 中间件行为：`aoteman_token` 存在 → 放行，不再跳登录页。

## 根因

1. `src/middleware.ts` 的软守卫只判断 Cookie 是否存在（`aoteman_token`），不校验有效性。
2. `src/hooks/useCurrentUser.ts` 把 `/api/auth/me` 的非 2xx / 网络异常统一转成 `user=null`，失败原因被吞掉。
3. `src/app/page.tsx` 身份初始化使用 `currentUser?.userId || 'anonymous'`，未登录即匿名，且首页没有登录守卫。
4. 对比 `src/app/admin/layout.tsx`：后台已有 `ready && !user → router.replace('/login')`，聊天首页缺失同样的守卫。

触发条件：浏览器带着失效 / 无法校验的 `aoteman_token` 访问 `/`（当前控制面未启动即触发）。

影响：用户被留在匿名工作台，接口 502、SSE 断流，且没有明确出口；继续发消息会落到 anonymous 身份。

## 方案

- 在 `src/app/page.tsx` 增加页面级守卫（与 `admin/layout.tsx` 保持一致）：
  - `authReady && !currentUser` 且是顶层窗口 → `router.replace('/login')`；
  - iframe 内嵌（`window.self !== window.top`）保持匿名可用，不跳转（沿用设计 §3.6 软守卫）；
  - 身份校验中 / 跳转中渲染「正在验证登录状态…」占位，避免先闪一帧匿名工作台，也避免用空 userId 发起会话 / SSE 请求。
- 不改 `middleware.ts`：保持「只看 Cookie」的软守卫，避免每次导航都请求控制面。
- 不区分 401 / 502：与后台一致，只要无法确认登录用户就回登录页；控制面不可用时登录页本身已有「服务暂时不可用」提示。

  `/api/sessions`、`/api/artifacts`、SSE 请求；Console 不再出现 SSE 重试错误。
