# 会话流串台与工具卡状态回退

- 日期：2026-11-06
- 模块：`src/app/page.tsx`、`src/hooks/useSSEStream.ts`、`src/app/api/sessions/[sessionId]/events/stream/route.ts`
- 状态：前端 P0 已验证；服务端 A/B/C 已完成，前端联调中
- 关联：`doc/design/2026-11-06-会话流与重复工具调用-服务端接口需求.md`（服务端 A/B/C 已交付）

---

## 1. 现象

1. 工具卡在「已完成」与「待执行」之间反复横跳；同一 `ask_followup_questions` 提交后过一会又弹出。
2. 切换会话后，B 会话先出现 A 会话的思考文本；切回 A 时历史从头重放。
3. Network 面板中同一个 session 出现多条 `after=0` 的 SSE 连接。

## 2. 复现与证据

### 2.1 同一 session 重复 `after=0`

在本地 `http://localhost:3000` 中依次点击会话 A → B → A，Network 面板记录：

```
reqid=41  GET /api/sessions/1792823877410-gdph68lvf/events/stream?...&after=0  [200]
reqid=43  GET /api/sessions/1791995261060-qs01crj9l/events/stream?...&after=0  [200]
reqid=45  GET /api/sessions/1792823877410-gdph68lvf/events/stream?...&after=0  [200]
```

同一个 session（`1792823877410-gdph68lvf`）被两次以 `after=0` 全量重放。
每次切换会话都清空本地 turns，再靠 `after=0` 重放历史，导致：
- 切回时历史重新渲染一遍；
- 旧连接的晚到事件写入新会话的全局 state（串台）；
- 游标 `lastSeq` 是全局一份，切换后从 0 开始，无法增量续传。

### 2.2 工具卡状态回退

服务端在 `TOOL_SUSPENDED` 分支会用同一个 `toolCallId` 再落一条 `state=pending` 的
`agent.tool_use`（`ConversationTurnService.java:735-753`、`875-889`）。
前端 `handleToolUse` / `handleSkillUse` 用 `{ ...t, ...toolUse }` 无条件覆盖：

```ts
// src/app/page.tsx（修复前）
if (existing) {
  return prev.map(t => t.id === toolUse.id ? { ...t, ...toolUse } : t);
}
```

后到的 `pending` 帧把 `success` / `error` 覆盖回 `pending`，并清空 `output` / `finishedAt`，
于是已提交的追问重新可提交。

### 2.3 追问幂等键不稳定

`handledFollowupIdsRef` 以「前端工具卡 id」为键，且 `clearConversation()` 时清空。
重复的 `agent.tool_use` 若拿到新的卡片 id（`event_start` / 重新 attach 后的 `evt_xxx`），
同一个 `toolCallId` 会被当成新追问再次弹出。

## 3. 根因

| # | 根因 | 位置 |
| --- | --- | --- |
| R1 | 工具卡合并允许「后到 pending 覆盖终态」 | `page.tsx` `handleToolUse` / `handleSkillUse` / `handleToolResult` |
| R2 | 追问幂等键用卡片 id、且随切会话清空 | `page.tsx` `handledFollowupIdsRef` |
| R3 | SSE 游标 / turnId 全局共享，会话切换重置为 0，旧连接回调无版本校验 | `useSSEStream.ts` `lastSeqRef` / `turnIdRef` / 连接回调 |
| R4 | 会话切换清空 UI 后完全依赖 `after=0` 重放，没有按会话保存已渲染快照 | `page.tsx` `switchSession` |
| R5 | SSE 代理在后端暂无回放事件时不立即 flush 响应头，EventSource 不触发 `onopen`，切回历史会话长期显示「未连接」 | `src/app/api/sessions/[sessionId]/events/stream/route.ts` |

## 4. 影响范围

- 工具卡状态机不可信，可能导致重复提交、服务端 `503 Invalid tool result IDs`；
- 多会话串流，历史重放与进行中流式文本交错；
- 无法做到「切走再切回接着看」（需服务端 B2 快照配合，但前端游标隔离是前提）。

## 5. 修复方案（P0）

1. **工具卡终态不回退**（`page.tsx`）
   - `handleToolUse` / `handleSkillUse`：已有卡片为 `success` / `error` 时，后到的 `pending` 只补空字段，
     不改 `status` / `output` / `finishedAt` / `startedAt`；
   - `handleToolResult` / `handleSkillResult`：同样禁止终态被 pending 结果覆盖。
2. **追问幂等**（`page.tsx`）
   - 幂等键改为模型侧 `toolCallId`（缺失时回退卡片 id）；
   - 按 `sessionId` 分桶保存，`clearConversation()` 不再清空；
   - 追问 / 工具确认提交加 `submittingRef` 防连点，并对工具确认增加「仍为 pending」校验。
3. **会话流隔离**（`useSSEStream.ts`）
   - `lastSeq` / `turnId` 改为 `Map<sessionId, state>`，切换会话取用本会话游标；
   - `connect()` 分配自增 generation，旧连接 / 旧会话的晚到回调直接丢弃；
   - `toolCallId -> cardId` 映射按会话隔离。
4. **按会话保存 UI 快照**（`page.tsx`）
   - 切换会话时保存当前渲染状态（messages / thinking / narrations / toolUses / 问卷 / 引用等）；
   - 切回时恢复快照，配合本会话 `lastSeq` 增量连接，不再全量重放；
   - `handleMessage` 对同 id 的流式消息允许用权威文本收尾，避免快照里的半截消息卡住。
5. **SSE 代理主动触发连接**（`src/app/api/sessions/[sessionId]/events/stream/route.ts`）
   - 改为 `ReadableStream` 手动转发后端流，并在开始处立即写一帧 `: connected` SSE 注释；
   - 后端无待回放事件时浏览器也能立刻触发 `onopen`，切回历史会话不再长期显示「未连接」；
   - 客户端断开时 abort 后端 fetch，避免连接泄漏；`dynamic = force-dynamic` 防止路由被静态优化。

### 6.2 Network 证据：游标按会话隔离

依次点击会话 A（`1791995261060-qs01crj9l`）→ B（`1792823877410-gdph68lvf`）→ A → B：

```

reqid=89  B  after=0   [200]   # 首次打开，全量回放
reqid=91  A  after=59  [200]   # 切回 A：本会话游标续传
```

修复前同一会话会被多次 `after=0` 全量重放；修复后第二次进入均为增量连接，且不同会话游标互不干扰。

### 6.3 浏览器实测

1. **工具卡终态不回退**：切换 A ↔ B 后，A 的 4 张 `list_files` 卡片仍为「已完成」，B 的 2 张知识库检索卡仍为「已完成」，未出现卡片重复。
2. **终态不被 pending 覆盖**：新建测试会话触发 `ask_followup_questions`，模型先产生一次参数校验失败（卡片「失败」），随后重试挂起（卡片「运行中」）；切换会话再切回后，失败卡仍为「失败」、挂起卡仍为「运行中」，失败卡没有被后到的 pending 帧拉回。
3. **追问只弹一次、提交后不复活**：第一轮 3 个问题作答并提交后问卷关闭；模型发起第二轮追问（新 `toolCallId`）时只渲染新问卷。切换会话再切回，仅剩第二轮问卷，第一轮未复活，工具卡数量与状态保持不变。
4. **追问提交防连点**：对「提交答案」执行双击，Network 中只有一条 `POST /api/sessions/.../events`（reqid=102），未产生第二次提交。
5. **SSE 连接状态**：切回历史会话（`after > 0`）与新建空会话均能立即显示「已连接」，不再长期停留在「未连接」。
6. **Console**：无 React / hydration / Fast Refresh 报错。

## 7. 服务端交付后的前端对接设计（2026-11-06）

> 依据：服务端接口文档 §11 与服务端实际代码
> （`ConversationEventPreviewBus.java:190-228`、`ConversationEventMapper.java:260-277`、
> `ConversationTurnService.java:1101-1128`、`ConversationController.java:90-124/351-363`）。

### 7.1 新增事件与字段

| 事件 / 字段 | 前端处理 |
| --- | --- |
| `preview.snapshot` | attach 时补发未落盘事件的完整文本；`seq=-1`，**不推进** `lastSeq` |
| 快照 `payload.events[].eventId` | 驼峰；与普通预览的 `event_id` 不同，不能混用 |
| 快照 `payload.events[].previewSeq` | 每会话递增；与普通 `event_start/event_delta` 的 `previewSeq` 共用防乱序 |
| `agent.tool_suspended` | 同一 `toolCallId` 的状态迁移；只更新已有工具卡为「等待确认」，不新建第二张卡 |
| `ToolUse.status='suspended'` | 状态优先级：`success/error > suspended > pending` |
| 重复提交单对象响应 | `{ accepted:false, reason:'DUPLICATE_TOOL_RESULT' \| 'DUPLICATE_TOOL_CONFIRMATION', turnStatus }`；静默忽略 |

### 7.2 SSE Hook 设计

1. `STREAM_EVENT_TYPES` 增加 `preview.snapshot`、`agent.tool_suspended`。
2. 每个会话的 `streamState` 增加 `previewSeqByEventId: Map<string, number>`：
   - `event_start` / `event_delta` / 快照条目统一按 `previewSeq` 校验；
   - 序号不大于已处理值的帧直接丢弃。
3. 快照条目：
   - 若同 `eventId` 已作为持久化事件处理，直接丢弃；
   - `agent.thinking` / `agent.message` 用完整 `text` 恢复流式段；
   - 工具用 `eventId` 作为卡片 id，`input = inputJson || text`，`status='pending'`；
   - **不写入** `seenEventIds`，否则后续同 id 的落盘事件会被误判重复。
4. `agent.tool_suspended`：
   - `toolCallId -> cardId` 映射到已有卡片；
   - 更新为 `suspended`，不新增卡片；
   - 若先于 `agent.tool_use` 到达，则先建立映射，后到的 `tool_use` 合并到同一张卡。
5. `session.error`：Hook 内结束 `isRunning`，页面同步结束流式状态与输入 loading。

### 7.3 页面设计

1. `submitEvent()` 返回三态联合：
   - `{ accepted:true }`
   - `{ accepted:false, duplicateReason }`
   - `{ accepted:false, error }`
2. 重复提交：不报错、不重试、不推进轮次、不追加用户确认消息；
   工具确认 / 追问问卷按服务端受理结果再推进本地状态。
3. `handleThinking` 改为按 id 幂等 upsert，快照完整文本覆盖同 id 流式段。
4. 新增 `onMessageSnapshot`：快照完整文本恢复流式气泡；已被落盘定稿的气泡不被覆盖。
5. 工具卡：
   - `pending` 显示「运行中」；
   - `suspended` 显示「等待确认」；
   - `success/error` 为终态，不被后到的 pending / suspended 覆盖。
6. `ProcessTimeline`：`pending` / `suspended` 都算未结束；存在 suspended 时标题显示「等待确认」。
7. 追问问卷：绑定工具接受 `pending` 或 `suspended`；提交成功后才 `beginUserTurn()`。
