# 历史轮次的「过程耗时」越刷新越大

- 日期：2026-11-06
- 模块：`src/hooks/useSSEStream.ts`、`src/app/page.tsx`（`ProcessTimeline` 耗时计算）
- 状态：已修复并实测
- 关联：`doc/bug/2026-11-06-会话流串台与工具卡状态回退.md`

---

## 1. 现象

刷新历史会话后，过程卡标题里的耗时异常偏大，而且**刷新越晚数字越大**：

```text
已完成思考 · 458.9s ...   （首次刷新）
已完成思考 · 630.2s ...   （几分钟后再刷新）
```

同一轮的真实执行时间只有几秒（该轮工具卡片自身的耗时分别为 0.39s / 0.33s）。

## 2. 根因

`ProcessTimeline` 的耗时取本轮所有步骤时间戳的最小 ~ 最大跨度：

```ts
const span = Math.max(...stamps) - Math.min(...stamps);
```

参与计算的 `stamps` 混用了两种时间：

| 来源 | 语义 | 是否可信 |
| --- | --- | --- |
| `tool.startedAt` / `tool.finishedAt` | 服务端落盘 `createdAt`（原始发生时间） | 可信 |
| `step.timestamp`（工具步骤） | `handleToolUse` 里的 `Date.now()`（前端接收时刻） | 回放时 = 现在 |
| `narration.timestamp` | `useSSEStream` 里的 `Date.now()`（前端接收时刻） | 回放时 = 现在 |

历史回放时，工具卡片上的 `timestamp` 和叙述的 `timestamp` 都被重置为「现在」，
与工具的真实 `startedAt` 组合后，跨度就变成了「本轮开始 → 现在」，刷新越晚越大。

## 3. 方案

- `agent.narration`：`timestamp` 改用 `data.createdAt`（缺失时才退回 `Date.now()`）；
- `ProcessTimeline`：工具步骤只取 `tool.startedAt` / `tool.finishedAt`，不再把卡片上的
  前端接收时刻计入耗时；思考 / 叙述 / 确认步骤仍用自己的时间戳。

不改任何接口字段，只纠正前端对时间戳语义的使用。

## 4. 验证

1. `node node_modules/typescript/bin/tsc --noEmit` → 通过；
2. `node node_modules/next/dist/bin/next build` → 通过；
3. 浏览器实测同一历史会话连续刷新多次：

```text
第 5 轮  glob_files             已完成思考 · 0.4s   （稳定）
第 6 轮  write_file             已完成思考 · 0.3s   （稳定）
第 7 轮  delete_file × 2       已完成思考 · 26.1s  （稳定）
```

耗时不再随刷新时间增长，且与工具卡片自身耗时一致（含用户确认等待的轮次仍按真实跨度显示）。
