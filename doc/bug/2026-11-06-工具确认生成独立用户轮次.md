# 工具确认被当成一轮新的用户输入

- 日期：2026-11-06
- 模块：`src/app/page.tsx`、`src/hooks/useSSEStream.ts`、`src/types/agent.ts`、`src/app/globals.css`
- 状态：已修复并实测
- 关联：`doc/design/2026-11-06-会话流与重复工具调用-服务端接口需求.md`、
  `doc/bug/2026-11-06-会话流串台与工具卡状态回退.md`

---

## 1. 现象

在第 7 轮（`请删除 lumi-approve-test.txt`）点击工具确认的「允许 / 拒绝」后：

1. 对话区多出一条用户气泡「已允许工具调用：delete_file」/「已拒绝工具调用：delete_file」，
   但用户并没有真的发消息；
2. 轮次计数 +1，后续回答被拆到「第 8 轮」，与触发它的工具卡不在同一轮；
3. 刷新历史会话时，已经确认过的工具又出现一张可点击的确认卡，点它会重复提交并可能返回
   `Invalid tool result IDs`；
4. 拒绝执行后工具卡一直停在「运行中」。

## 2. 复现与证据

同一会话 `1793964079459-86huzj475` 第 7 轮的服务端落盘事件：

```text
seq=167  agent.tool_use        name=delete_file  toolCallId=call_...
seq=169  session.requires_action  reason=tool_confirmation
seq=173  user.tool_confirmation   allow=false          <- 用户拒绝
seq=180  agent.message                                <- 收尾回答
seq=182  session.status_idle
```

确认前后**没有**新的 `user.message`，即服务端从未把确认当成新一轮输入；轮次被推进完全是
前端本地行为。

## 3. 根因

| # | 根因 | 位置 |
| --- | --- | --- |
| R1 | 提交确认前调用 `beginUserTurnRef.current?.()` 并追加本地用户消息 | `page.tsx` `submitToolConfirmation`（修复前） |
| R2 | 历史回放只订阅 `session.requires_action`，未订阅 `user.tool_confirmation`，确认卡没有终态 | `useSSEStream.ts` |
| R3 | 拒绝时服务端不会再补 `agent.tool_result`，工具卡没有任何收尾信号 | `useSSEStream.ts` / `page.tsx` |
| R4 | 历史回放的顺序是「结果/确认 → requires_action」时，迟到的 `requires_action` 仍会新建确认卡 | `page.tsx` `handleToolConfirmation` |

## 4. 方案

1. **确认不是用户输入**（`page.tsx`）
   - 不再 `beginUserTurn()`、不再插入「已允许/已拒绝工具调用」用户气泡；
   - 工具结果与后续回答继续归入原挂起轮次，确认动作不单独呈现。
2. **确认事件是确认卡终态**（`useSSEStream.ts`）
   - 订阅 `user.tool_confirmation`，读取 `payload.tool_use_id` / `payload.allow`，
     回调 `onUserToolConfirmation(toolCallId, allow)`；
   - 实时提交与历史回放共用页面同一个 `handleUserToolConfirmation`。
3. **终态先到时屏蔽迟到帧**（`page.tsx`）
   - 新增 `settledToolCallIdsRef`：`agent.tool_result`、`user.tool_result`、
     `user.tool_confirmation` 任一先到时写入；
   - `handleToolConfirmation` 先查该集合，已终态则直接忽略。
4. **拒绝后本地收尾**（`page.tsx` + `types/agent.ts` + `globals.css`）
   - `ToolUse.status` 新增 `cancelled`，与 `success` / `error` 同为终态；
   - 用户拒绝时把 `pending` / `suspended` 工具卡置为 `cancelled`，输出「用户已拒绝执行」；
   - 状态单向推进，后续回放的 `pending` / `suspended` 不会把卡片拉回「运行中」。
5. **幂等提交**（`page.tsx`）
   - `submitEvent()` 返回 `DUPLICATE_TOOL_CONFIRMATION` 时静默收尾：不提示、不追加消息、
     不推进轮次；真失败保持 `pending` 允许重试。

## 5. 验证

1. `node node_modules/typescript/bin/tsc --noEmit` → 通过；
2. `node node_modules/next/dist/bin/next lint` → 无告警；
3. `node node_modules/next/dist/bin/next build` → 通过；
4. 浏览器实测（`http://localhost:3000`，会话 `1793964079459-86huzj475`）：
   - 允许 / 拒绝确认后不再出现新的用户气泡；
   - 轮次仍停在第 7 轮，没有生成第 8 轮；
   - 拒绝后工具卡立即变为「已取消」，刷新后仍保持；
   - 刷新历史会话不再出现可点击的确认卡，追问问卷显示「已完成」；
   - Console 无 error / warn。
