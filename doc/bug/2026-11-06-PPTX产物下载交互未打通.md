# PPTX 产物下载交互未打通

- 日期：2026-11-06
- 范围：`aoteman-web` 对话页产物（Artifact）交互
- 关联服务端提交：`ac77672 支持PPTX产物下载`（`aoteman-platform`）

## 1. 现象

服务端已经支持 PPTX 产物列举与下载，但用户在对话页看不到 PPTX 产物入口，也没有可点击的下载按钮，表现为「前端没有实现 PPTX 交互」。

## 2. 复现与证据

### 2.1 服务端 / BFF 链路正常

以真实工作区文件 `泰国之旅计划.pptx`（49145 字节）实测：

| 请求 | 结果 |
| --- | --- |
| `GET /api/artifacts?userId=<uid>` | `200`，返回该 PPTX，`previewable=false`、`downloadable=true`、`contentDisposition=attachment` |
| `GET /api/artifacts/content?...&download=true`（数据面 8080） | `200`，`Content-Type` 为 PPTX MIME，`Content-Disposition: attachment`，49145 字节 |
| 同一路径不带 `download=true` | `415`（符合设计：PPTX 不支持在线预览） |
| 前端 BFF `localhost:3000/api/artifacts/content?...&download=true` | `200`，正确透传 `content-type` / `content-disposition` / 文件字节 |

结论：**下载能力与 BFF 代理已经可用，不是服务端问题。**

### 2.2 前端已有 PPTX 视图，但入口缺失

代码现状：

- `src/lib/artifacts.ts`：`artifactKind()` / `artifactContentUrl(..., download=true)` 已支持 `pptx`。
- `src/components/artifacts/PptxArtifactView.tsx`：已实现文件信息 + 「下载 PPTX」。
- `src/components/artifacts/ArtifactCanvas.tsx`：已按 `kind === 'pptx'` 渲染上述视图。
- `src/app/api/artifacts/**`：列表与内容代理已实现。

真正的断点在入口：

1. 对话页唯一的产物入口是每轮回答下方的 `TurnArtifacts` 卡片；
2. 卡片数据来自 `matchTurnArtifacts(turn.toolUses, artifacts)`；
3. `isArtifactWrite()` 只认 `write_file` / `edit_file`，并且要求工具 `input.path` 以 `.md/.markdown/.pptx` 结尾；
4. PPTX 是二进制文件，实际由 PPT 技能通过 `execute` 执行 `node scripts/generate.js ...` 等方式生成，**不会**走 `write_file`，因此该轮卡片为空；
5. 页面没有「工作区产物」总入口，未被某一轮 `toolUses` 匹配到的产物（历史文件、脚本生成文件）在 UI 上完全不可达。

影响范围：

- PPTX 产物：能力已上线但用户不可发现、不可下载；
- Markdown 产物：由脚本/命令生成或历史遗留、未被 `write_file` 记录的同样不可达。

## 3. 根因

前端把「本轮产物」错误地等同于「`write_file` / `edit_file` 的 `input.path`」，而 PPTX 只能由 `execute` 生成；同时缺少一个不依赖工具调用的工作区产物入口。服务端元数据（`workspacePath/size/modifiedAt`）其实已足够展示与下载。

## 4. 修复方案

### 4.1 扩展本轮产物识别（`src/lib/artifacts.ts`）

- 保留 `write_file` / `edit_file` 的路径匹配；
- 新增 `execute` 工具识别：解析 `command` / `working_directory`，仅提取 `.pptx` 路径参与匹配。
  - 只对 `.pptx` 放宽，避免 `cat README.md` 之类的读操作被误判为产物；
  - 路径按 `/` 规范化，沿用现有「路径段后缀双向匹配」。
- `isArtifactWrite()` 同步覆盖 `execute + .pptx`，使产物列表在该轮内及时刷新。

### 4.2 新增工作区产物入口（顶栏「产物」）

- 新增 `WorkspaceArtifactsSheet`：列出 `/api/artifacts` 返回的全部产物（Markdown / PPTX），展示文件名、路径、大小、修改时间、类型；
- 顶栏加入「产物」按钮，带数量徽标；移动端只显示图标；
- 点击条目打开右侧产物画布（Markdown 预览 / PPTX 文件信息 + 下载）；
- PPTX 行额外提供直接下载按钮（`download=true`）；
- 空态文案「暂无产物」。

### 4.3 文案修正

- PPTX 卡片副标题由「点击预览」改为「打开 / 下载」，避免误导（PPTX 不做页面级预览）。

## 5. 验证方式

1. `node node_modules/typescript/bin/tsc --noEmit` 通过；
2. `git diff --check` 通过；
3. 浏览器实测（Chrome DevTools MCP）：
   - 工作区放入真实 `.pptx` 后，顶栏「产物」按钮显示数量；
   - 打开面板能看到 PPTX 行；
   - 点击行打开画布，显示真实文件信息与「下载 PPTX」；
   - 点击下载发起 `/api/artifacts/content?...&download=true`，响应 `200` + `attachment`；
   - 控制台无报错。
4. 回归：Markdown 产物卡片仍可打开画布并渲染正文。

## 6. 非目标
